# 測定基準 v1

- 状態: 発効（2026-09-06 合意）
- 適用: これ以降に立てる全プラン。過去の結果は `docs/EVIDENCE_RECLASSIFICATION.md` の分類に従う
- 位置づけ: `docs/MEASUREMENT_DESIGN.md` が「過去に何が起きたかの監査」、本書が「これから何をするかの規則」

この基準は、過去に 23 件の比較が検出力不足のまま結論として扱われ、
陽性に見えたものが再現しなかったことへの対処として作られた。
規則はすべて「走らせる前に通る関門」であって、後から掃除する手順ではない。

---

## 1. 命名規則

### 1.1 形式

    LOSS(params) @STATE /SELECTOR

| 欄 | 意味 | 値 |
|---|---|---|
| `LOSS` | 何をするか（損失族） | 閉じた一覧から選ぶ（1.3） |
| `(params)` | 係数。凍結値を書く | `λ=0.054` |
| `@STATE` | どのサンプルに作用するか | canonical 状態の述語式。`S2×T1` `CW` `S2×(T1\|T2)` `all` |
| `/SELECTOR` | 所属の判定時点 | `online` または `fixed@e99` |

### 1.2 短縮名

**短縮名 = 正式名から、その比較の中で変化しない欄を落としたもの。**

PM の2候補は選択規則しか違わないので `PM(online)` と `PM(fixed@e99)`。
λ を振るときは `PM(λ=0.054)` と `PM(λ=0.11)`。
正式名は常にフル4欄。短縮名は文中だけの略記であり、登録簿には書かない。

### 1.3 損失族の語彙（閉じた一覧）

`AdvCE` `CleanCE` `TargetSoften` `KDScale` `TPFM` `MF` `PM` `BD` `SBD` `Aug` `Order`

新しい族を足すときは、既存のどれとも異なることを登録時に示す。

### 1.4 旧名との対応

| 旧名 | 正式名 |
|---|---|
| DPM | `PM(λ=0.054) @S2×T1 /fixed@e99` |
| OS-PMP | `PM(λ=0.054) @S2×T1 /online` |
| ST1W | `AdvCE(β=0.071) @S3×T1 /fixed@e79` |
| T1WCONF | `AdvCE(β=0.075) @S3×T1 /fixed@e79` |
| S3FIX075 | `AdvCE(β=0.075) @S3∧¬CW×Tcorrect /fixed@e80` |
| S3DYN075 / INST075 | `AdvCE(β=0.075) @S3∧¬CW×Tcorrect /online` |
| CW-TPFM（旧 A7 margin-only） | `TPFM @CW /fixed@e79` |
| A1 = C10 = G1 = F1 | `CleanCE(β=0.15) @CW /fixed@e79` |
| I100 | `Aug(CropShift→IDBH_WEAK@e100) @all /none` |

### 1.5 「dynamic」の廃止

この語は plan 0079 では「動的ターゲット・固定コホート」、plan 0087 では「動的コホート」を指していた。
以後この語は使わない。判定時点は `/online` と `/fixed@eN` でのみ表す。

### 1.6 名前に入れるもの・入れないもの

- **arm 名に入れる**: 処置を再構成するのに必要なもの（損失・係数・対象・選択規則）
- **campaign 記録に入れる**: 測定を再構成するのに必要なもの（環境世代・ソース SHA・親 checkpoint・seed・複製番号・horizon・対照構成）

同じ arm を別の seed 数や別の horizon で走らせたものは、**同じ arm の別の測定**であって別の arm ではない。

### 1.7 登録が事前の関門であること

> **arm は、登録簿に登録されていなければ走らせられない。**

新しい処置を走らせる前に `docs/ARM_REGISTRY.md` に正式名を書き込む。
**そのとき既に同じ行があれば、それは新しい実験ではなく再実行である。**

前提として canonical 状態の定義は1つに統一する。
旧 `ert_state_overlay_v1` の S1/S2/S3 は「歴史的定義」として隔離し、新しい式には使わない。

## 2. 測定の単位

### 2.1 推論の単位は「親」

床 0.25–0.50 pp は同じ親から分岐した2本の差であり、**再開後のノイズのみ**を測っている。
親そのもののばらつきは含まれない。
「処置が効く」という主張は親をまたいで成り立つ必要があるので、**推論の単位は親**とする。

### 2.2 標準構成

- **親 6 本**（I100 e99 相当を新規に生成する）
- 親ごとに **処置枝と対照枝を対で**分岐（同じ `continuation_seed`）
- 親ごとに **複製 2 本**
- 検定は **親レベルの対比較 6 対**（自由度 5）

複製は各親の対差のノイズを平均で下げるためのものであり、自由度を増やすものではない。

### 2.3 対照

対照は必ず**同一プラン内で同時に走らせる**。過去の対照を流用しない。
処置枝と対照枝は親・`continuation_seed`・環境世代・ソース SHA をすべて共有する。

## 3. horizon と終端

- 判定は **LR 減衰後**で行う（milestones [100,150], gamma 0.1）。減衰前は床が 1.14–1.25 pp あり、
  かつ horizon をどれだけ伸ばしても縮まらないため、減衰前の延長には意味がない。
- スクリーンの終端は減衰後の固定エポックとし、プランに明記する。
- 確定の終端は **e199**。

### 3.1 橋渡し検証（スクリーン導入の前提）

短期スクリーンの判定が全訓練の判定と一致する保証は現時点で**無い**。
スクリーンを道具として使う前に、**e199 の結果が既知の arm を 2〜3 本**選び、
新しいスクリーンに通して**符号と順位が一致するか**を確認する。

- 一致した場合: スクリーンを採用し、以後の探索に使う
- 一致しない場合: スクリーンを破棄し、全訓練のみで判断する

この検証が終わるまで、スクリーンの結果を根拠にした結論を出さない。

## 4. 判定指標と test set の見方

本プロジェクトは既に official train を層化分割して **train 45000 / validation 5000** で
訓練しており（`stratified_train_validation_split`）、`val_clean_accuracy` と `val_pgd_accuracy`
を毎エポック記録している。判定はこの既存の分割の上で行う。

| 段階 | 指標 | データ |
|---|---|---|
| スクリーン | PGD-20 | **既存の validation 5000**（train から層化分割された held-out） |
| 確定 | AutoAttack | **official test 10000** |

- スクリーンは test に一切触れない。test は確定でのみ見る。
- **test を見る回数は、1つの知見につき事前にプランで宣言する。**
  標準は 1 回（＝ 6 親 × 処置/対照 の 12 評価）。
- **`validation_fraction` と `split_seed` は 1 つの比較の中で必ず同一**にする。
  異なれば validation 集合そのものが変わり、対比較が成立しない。
- 標準精度と 1 エポックあたりの実測時間を、両段階で必ず併記する
  （主張が「標準精度と計算コストを維持・改善しつつ」である以上、これは主要指標の一部）
- 訓練データが 45000 であることは本プロジェクトの既存設計であり、
  公開ベースライン（50000 訓練）と数値を並べるときは必ずその旨を注記する。

## 5. 検出力

### 5.1 必要数

対比較の差の標準偏差を σ_d、両側 α=0.05、検出力 80% とすると n = 7.85·σ_d²/δ²。

σ_d = 0.35 pp（**暫定値。plan 0092 で確定させる**）のとき:

| 検出したい効果 δ | 必要な対の数 |
|---:|---:|
| 1.0 pp | 1 |
| 0.7 pp | 2 |
| 0.5 pp | 4 |
| 0.35 pp | 8 |
| 0.3 pp | 11 |
| 0.2 pp | 24 |

### 5.2 標準構成の到達点

親 6 本 × 複製 2 本のとき、各親の対差の σ は 0.35/√2 ≈ 0.25 pp。
親レベル 6 対での検出可能効果は **約 0.28 pp**（自由度 5）。

参考: 親 4 本 × 複製 2 本なら約 0.35 pp（自由度 3）。

### 5.3 事前宣言

**走らせる前に「検出したい最小効果」を宣言し、親と複製の数をそこから導く。**
宣言した効果を検出できない設計の arm は、走らせない。

### 5.4 採択規則

主要 arm は、**親レベル対比較の平均差 > 0 かつ 95% 信頼区間の下限 > 0** のとき採択する。
それ以外は不採択。効果量と信頼区間を必ず併記し、p 値のみの報告はしない。

## 6. 係数

### 6.1 較正と丸め

1. 処置ごとに勾配比の中央値 0.25 を狙って較正する（処置ごとに1つ。結果を見ての再調整はしない）
2. 較正値を **有効数字 2 桁に丸める**
3. **丸めた値を凍結して走らせる。報告値も同じ。**

生の較正値で走らせて丸めた値を報告することはしない。

| 生の較正値 | 凍結値 |
|---|---|
| 0.05380932585058825 | λ = 0.054 |
| 0.07095924764871597 | β = 0.071 |
| 31.649566509850324 | 32 |

### 6.2 近傍検査（主要 arm のみ）

主要 arm は **λ/2 と 2λ の両側**を走らせる（計 3 点）。
2 倍の係数変化を跨いで符号を保てば、丸めにも較正誤差にも耐えている。
保てなければ、その知見は脆いものとして扱い、そこで止める。

非主要 arm には近傍検査を行わない。

### 6.3 用量不足の救済（機構作動ゲート）

較正点で効かなかった非主要 arm を捨てる前に、**機構が作動したかどうか**を見る。
処置が狙っている量（PM なら選択サンプル上の生徒 adv pair-margin）を処置枝と対照枝で測り:

| 機構の作動 | ロバスト精度 | 判定 |
|---|---|---|
| 動いた | 動かない | 機構は働いたが利益なし → **棄却**。係数は原因ではない |
| 動かない | 動かない | 用量不足 → **2λ を 1 点だけ追試** |

引き金は結果変数ではなく工程変数（損失が狙った量を実際に動かしたか）なので、
「結果を見ての再調整なし」に反しない。
2λ で陽性が出た場合、それは採択ではなく**次プランの主要 arm 候補への昇格**にとどめる。

閾値はプランで事前に宣言する。

## 7. 事前宣言

プラン 1 件 = 家族 1 つ。走らせる前にプラン内に次を書く。

1. arm 一覧（正式名）
2. **主要 arm を 1 本だけ指名**。残りは副次または探索として明示
3. 検出したい最小効果
4. そこから導いた親の数と複製の数
5. 判定指標（スクリーン / 確定）と、全 test を見る回数
6. 採択規則（5.4 からの逸脱があれば理由とともに）
7. 機構作動の測定量と閾値（6.3）

**副次で出た陽性は「次プランの主要 arm 候補」であって、それ自体は結論ではない。**
主要を 1 本に絞ることで多重比較の補正議論を回避する。

---

## 8. 不変条項

1. 1 つの比較が 2 つの環境世代をまたがない（`requirements/environment.lock`）
2. 処置ごとに較正係数は 1 つ。結果を見ての再調整はしない
3. checkpoint の**ファイルハッシュで再現性を判定しない**。`tracker_run_id` が実行ごとに変わるため
   ファイルは必ず異なる。比較するのは model `state_dict` のバイト列
4. 状態定義（S1/S2/S3, T1/T2/T3, CW）は 1 つだけ。旧定義は歴史的記録としてのみ残す
