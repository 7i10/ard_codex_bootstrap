## 選択肢

### A: 記録だけで閉じる（おすすめ）

- **GPU時間**: 0。
- **わかること**: 新しいことはありません。「重なりのある線形 stem は、同じ source・ホスト・seed の比較で PGD-10 −0.47 / clean −0.39（Phase 2 のルールで効果なし）、当てはまりもわずかに下がる」と記録します。
- **事前ルール**: Phase 2 のルールで「効果なし」（|差| < 0.5pt）は「採用しない」です。ConvNeXt-Atto の stem は標準の 4x4 パッチ化のままにします。
- **リスク**: 境目まで 0.03pt なので、本当の差が −0.5〜−1pt（「保留」で下がる側）である可能性も残ります。ただ、どちらでも採用にはならないので、判断は変わりません。論文に書くときは「seed 1本で上がらなかった」とだけ書きます。

### B: ols 版の seed 1 を回す

- **GPU時間**: 約 27〜36 時間。この run の実測 35.28 時間（共有の Ferret）と、Hamster での標準の Atto の速さ（713〜716 枚/秒、cosine run で 25.23 時間）に計算量 +5.3% を掛けた約 27 時間の間をとりました。
- **やり方**: `imagenet_convnext_atto_ols_pgd_at_phase2_adamw_random_lr1em3.yaml` を seed 1 で、seed 0 と同じ `9a16cd6` の worktree から回します。比べる相手は既にある Phase 1 の ConvNeXt-Atto lr 1e-3 seed 1（Ferret で実行済み）。その clean / PGD-10 は run の前に Ferret の bundle から読んで plan に書き写します。
- **わかること**: seed 1 でも上がらないか。
- **事前ルール**: d1 = ols 版 seed 1 − Phase 1 seed 1（最後の普通の重み、取り分けた画像すべての PGD-10）。d1 < +0.5pt → 「2本とも上がらない」として閉じる。d1 ≥ +0.5pt → seed 0 と向きが逆なので「判定できない」と記録し、追加するかは改めて packet で決める。2本の平均やばらつきは出しません。
- **リスク**: Phase 1 seed 1 は EMA なしの設定・別の source で、設定の違いが混ざります。期待される差（seed 0 で −0.47）は noise floor より小さく、2本目でも判定できない見込みが高いです。約 30 時間を、ほぼ確実に「閉じる」で終わる確認に使うことになります。

### C: 0057 B' の β2 = 0.95 の組に ols 版を1本加える

- **GPU時間**: 約 27〜36 時間（B と同じ見積もり）。そのうえ、計画（plan 0103）への追記と、β2 = 0.95 の ols 用 config の作成・レビューが先に要ります。
- **わかること**: 0057 B' で β2 = 0.95 が標準になった場合に、その設定でも stem を変えて上がらないか。0057 B' の「stem なし β2 = 0.95」と同じ source・同じ設定で比べるので、stem の効果だけを見られます。
- **事前ルール**: ols 版 β2 = 0.95 − 0057 B' の ConvNeXt-Atto「stem なし」β2 = 0.95（最後の普通の重み、取り分けた画像すべての PGD-10）に Phase 2 のルール（≥1.5pt「効果あり」、0.5〜1.5pt「保留」、<0.5pt「効果なし」）。
- **リスク**: β2 = 0.95 は 0057 B' でまだ結果が出ていない設定です。β2 = 0.999 で上がらなかった stem が β2 = 0.95 なら上がる、という理由は今のところありません（ols 版は β2 = 0.999 でも普通に学習しており、0057 で β2 が効いたのは ConvStem の崩れを抜け出す点でした）。0057 B' の結果を見てから決めても遅くありません。

## おすすめ: A

条件のそろった比較（同じ source・ホスト・seed）で、PGD-10 も clean もすべてのチェックポイントで下がる側に出ており、Phase 2 のルールでは「効果なし」です。
B と C はどちらも、出てくる差が noise floor（seed の差 0.36pt、CIFAR では 1〜2pt）より小さい見込みが高く、得られる結果で採用に変わる道筋がほぼありません。
batch B の3本（深く細い版・ConvStem 版・ols 版）がどれも標準の Atto を上回っていないので、ConvNeXt-Atto の形の改良に GPU を回すより、上がる向きで「保留」になっている問い（0052/0053 の cosine、0058 のラベルスムージング）や、0057 B' の決定済みの run に回すほうが得るものが大きいと考えます。

**判断が変わる場合**:
- 論文の表に stem の行を seed 2本でそろえて載せたい場合 → B。
- 0057 B' で β2 = 0.95 が ConvNeXt-Atto の標準になり、その設定で stem の行をそろえたい場合 → C（B' の結果が出たあとに）。
