# 0023: MobileViT-S の ImageNet-100 グリッド完了。ImageNet-1k の学習率をどう決めるか

## 結果のまとめ

記録: `docs/plans/0103-lightweight-imagenet-architecture-survey.md` の Progress log、
2026-09-30 (postrun, pretrained / 2.5e-4)。証拠台帳 `docs/RESEARCH_STATUS_SUMMARY.md` の最終行。
この契約には集計スクリプトが無いので、`docs/experiments/` の record はありません
（plan 0103/0104 の他の hand-run と同じ扱い）。

条件: ImageNet-100 代理データ、MobileViT-S、plain PGD-AT（教師なし）、seed 0、
l_inf 4/255、学習時 PGD-3、評価 PGD-10。AdamW、wd 0.01、50 epoch。
数字はすべて内部検証（学習用データから取り分けた 2,564 枚）で、公式テストではありません。
AutoAttack はまだ走っていません。

内部検証 PGD-10（%）、学習率 低 → 高:

| 初期化 | 学習率 | best | last | best の clean |
|---|---|---:|---:|---:|
| 事前学習済み | 6.25e-5 / 1.25e-4 / 2.5e-4 | 57.88 / 60.65 / **62.56** | 57.18 / 59.83 / **61.66** | 83.62 / 85.57 / 87.21 |
| ランダム | 1.25e-4 / 2.5e-4 / 5e-4 | 37.13 / 46.65 / **50.51** | 36.27 / 45.94 / **50.16** | 56.28 / 66.61 / 71.92 |

- どちらの初期化でも、最大値はグリッドの上端です。
- 事前学習済みの上位2点の差は PGD-10 で +1.91pt（best 同士）です。
  2つの検証値の差の標準誤差は約 1.4pt なので、約 1.4 SE にとどまります（seed は各1本）。
- 事前学習済みとランダムの差は、各グリッドの best 同士で PGD-10 +12.05pt、clean +15.29pt です。
  差の向きははっきりしています。ただし両方とも最大値が上端にあるので、差の大きさは確かではありません。
- 学習に使った画像と未使用の画像の差（probe − val、最終 epoch）は、学習率とともに広がります。
  PGD-10 で +6.8 / +10.1 / +13.8 です。ImageNet-100 では過学習寄りです。
  一方、ImageNet-1k は学習不足寄りです（A2 判定で指摘済み）。

守るべき既存の判定:

- **A2（2026-09-29）**: ImageNet-100 の代理学習は、学習率の選択には使えません。
  plan 0104 stage 3 では最大値の位置がずれ、順位が逆転しました。
  事前学習済み: ImageNet-100 は 0.05 が最大、ImageNet-1k は 0.015 が最大。
  ランダム: ImageNet-100 は 0.1 が最大、ImageNet-1k は 0.025 が最大。
  代理学習で使えるのは、初期化の比較（差の向き）だけです。
- **公平性の原則（A2）**: モデルごとに調整の予算をそろえ、best 同士で比べます。
  MobileNetV4-S は ImageNet-1k で学習率3点（初期化ごと）を使いました。
- 経験則（証拠は SGD の1モデルだけで、論文の根拠にはならない）: ImageNet-1k の最適値は、
  ImageNet-100 の最大値以下になりそうです。plan 0104 では1〜2段階下でした。
  今回それを当てはめると、MobileViT-S 事前学習済みの ImageNet-1k の最適値は
  1.25e-4 か 6.25e-5 あたりと予想されます。どちらも承認済みのグリッドの中です。

## ノイズの目安

- ImageNet-1k の内部検証は 25,620 枚あります。PGD-10 が 30% 前後のとき、1回の測定の SE は約 0.3pt です。
- MobileNetV4-S Arm A の seed 0 と seed 1 の差は、最終 PGD-10 で 0.01pt でした。
- plan 0104 は判定の閾値を **1pt** にしました。本パケットでも同じ閾値を使います。
  1pt 未満の差は「区別できない」と記録し、結果としては読みません。
- 注意点: MobileNetV4-S の事前学習済みグリッドでは、ImageNet-1k の3点の幅が 1.34pt しかありませんでした
  （30.58 / 31.92 / 31.26）。MobileViT-S でも上位2点が 1pt 以内に収まる可能性は高いです。

## コストの前提

- ImageNet-100 で測った MobileViT-S の速度は 214 img/s です（`torch.compile`、fp32、Hamster の 4090）。
- ImageNet-1k の学習画像は約 125.6 万枚（98%）です。計算すると 1 epoch 約 1.6 時間、
  PGD-10 の検証を足して約 1.7 時間です。
- 50 epoch で1本 **約 80-100 GPU時間（3.4-4.2日）** になります。
- 以前の SGD の MobileViT-S ランダム初期化の run の見積もりは「約4日」でした。上の計算と一致します。
- 1枚の GPU に2本同時に載せると、速度が落ちるので考えません。

## 選択肢

### A: ImageNet-1k で承認済みの3点を回す（推奨）

- **内容**: MobileViT-S、事前学習済み、AdamW、wd 0.01、50 epoch、学習率 {6.25e-5, 1.25e-4, 2.5e-4}。
  レシピは B1/B2・B3 で承認済みなので、新しい契約ではありません。
  やることは ImageNet-1k 用の config を書き、source を固定し、`/experiment-launch` で起動することです。
  経験則で当たりそうな 6.25e-5 と 1.25e-4 を Hamster の2枚で先に回し、2.5e-4 は後で回します。
- **GPU時間**: 約 240-300。実時間は約7日（2本並行で1巡、1本で1巡）。
- **わかること**: MobileViT-S 事前学習済みの ImageNet-1k の学習率を、MobileNetV4-S と同じ予算・同じ指標で決められます。
  経験則「ImageNet-100 の最大値が上限」が2モデル目でも成り立つかも確かめられます。
- **事前登録ルール**:
  - 採用する学習率は、最終 epoch（49）の内部検証 PGD-10 が最大の点（plan 0104 と同じ指標）。
  - 上位2点の差が 1pt 未満なら「区別できない」と記録します。best 同士の比較には最大の点を使い、
    同点に近いことを明記します。
  - 最大値が上端（2.5e-4）で、しかも 1pt 以上勝っている場合は、グリッドを足さずに人間に戻します
    （足すとモデル間で予算がそろわなくなるため）。
- **リスク**: 約1週間 Hamster を占有します。seed は1本だけです。
  3点が 1pt 以内に収まると、学習率の選択そのものが決まらない可能性があります。

### B: 2点だけ先に回し、条件付きで3点目を足す

- **内容**: A と同じ条件で {6.25e-5, 1.25e-4} を Hamster の2枚で並行に回します。
- **GPU時間**: 約 160-200（実時間 約3.5-4日）。条件を満たせば、さらに約 80-100 を足します。
- **わかること**: 経験則が正しければ、A より約3日早く同じ答えが出ます。
- **事前登録ルール**:
  - 1.25e-4 の最終 PGD-10 が 6.25e-5 より 1pt 以上高いときだけ、2.5e-4 を足します。
  - そうでなければ2点で打ち切り、最大の点を採用します。
- **リスク**: 打ち切った場合、MobileViT-S は2点、MobileNetV4-S は3点になり、A2 の「予算をそろえる」に反します。
  打ち切りの判断に、信頼性が低いと分かっている経験則を使うことになります。

### C: 何もしない（他モデルのグリッドを待つ）

- **内容**: 新しい GPU ジョブは入れません。DeiT-Tiny と ConvNeXt-Atto の ImageNet-100 グリッドがそろってから、
  AdamW 系3モデルの ImageNet-1k の学習率の決め方（A2 で「未決」）をまとめて決めます。
- **GPU時間**: 0。Hamster の2枚は空いたままです。
- **わかること**: 新しいことは何もわかりません。ただし、3モデルに同じ方法を当てはめることが保証されます。
- **事前登録ルール**: 残りの ImageNet-100 セルがすべて `completed` になった時点で、新しい決定パケットを書きます。
  それまで ImageNet-1k の AdamW ジョブは起動しません。
- **リスク**: MobileViT-S は1本約4日かかり、Phase 1 で一番遅いモデルです。
  ここで待つと、Phase 1 全体の完了がそのまま遅れます。

### 検討して外した案

- **ImageNet-100 で 1.25e-4 と 2.5e-4 に seed を足し、上位2点を区別する案**: 外しました。
  A2 で、代理学習の順位は ImageNet-1k の学習率選びに使えないと判定済みです。
  区別できても、使い道がありません。
- **ImageNet-1k を epoch 25 で打ち切って比べる案**: 外しました。
  plan 0104 では、学習率の減衰のたびに順位の差が縮みました（random 0.025 のリード: +2.78 → +1.73 → +0.66pt）。
  途中の epoch は信頼できる代理になりません。やるなら、スケジュールを変える新しい契約と新しい plan が必要です。

## 推奨の理由

A を推奨します。A2 の公平性の原則（モデルごとに同じ予算、best 同士）を守ったまま、
ImageNet-1k の学習率を直接決められるのは A だけです。
MobileNetV4-S もこの方法（ImageNet-1k で3点）で学習率を決めました。
いまの Hamster は2枚とも空いています。MobileViT-S は一番遅いモデルなので、
先に始めるほど Phase 1 全体が早く終わります。
経験則で当たりそうな2点を先に回すので、B の早さの利点の大部分は A でも得られます。
しかも打ち切りをしないので、予算は3点のままそろいます。

判断が変わる条件は次の2つです。

- AdamW 系の学習率の決め方を、3モデル共通でグリッド以外の方法にしたい場合
  （例: 文献の線形則で1点に固定する）。このときは C を選び、方法を先に決めるべきです。
- Hamster を別の優先度の高い仕事（例: AutoAttack の評価）に回したい場合。
  このときは C を選ぶか、A の3点目を後回しにします。
