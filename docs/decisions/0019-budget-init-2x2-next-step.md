# 0019: 予算×初期化 2x2 の結果と次の一手

## 結果（証拠）

詳しい数字は plan 0103 の Progress log（2026-09-25 の項）とコミット `ffa61c9` にあります。
この契約には集計スクリプトがないので、`docs/experiments/` のレコードはありません。
plan 0102/0103 の他の hand-run と同じ扱いです。

すべての数字で条件は共通です。
- データとモデル：ImageNet-1k、MobileNetV4-Conv-Small、普通の PGD-AT、教師なし、seed 0。
- 脅威モデル：l_inf 4/255。
- 評価：PGD-10（ステップ 8/765、ランダムスタートあり）。
- 実行環境：1 GPU、バッチ 128、RTX 4090。
- val：学習用分割のうち学習に使わない 2%（25,620 枚）で測った**内部検証**です。公式の ImageNet val ではありません。
- AutoAttack はまだ実行していません。

| セル | last（epoch 99 / 49）clean / PGD-10 | best（val PGD 最大）clean / PGD-10 |
|---|---:|---:|
| 事前学習・100 epoch | 55.21 / 30.70 | 54.88 / 31.03（ep 91） |
| ランダム初期化・100 epoch | 54.56 / 30.58 | 54.44 / 30.68（ep 97） |
| 事前学習・50 epoch（Arm A、seed 0） | 54.57 / 30.58 | 54.57 / 30.74（ep 46） |
| 事前学習・50 epoch（Arm A、seed 1） | 54.33 / 30.59 | — |
| ランダム初期化・50 epoch | 未実施 | — |

わかったこと：
1. **どの差もとても小さいです。** clean の差は最大 0.65pt、PGD-10 の差は最大 0.35pt です（best でも last でも）。
2. **事前学習の有利さは途中で消えます。** epoch 0 では事前学習の方が clean で 45pt 上です。しかし lr 0.05 の区間で、事前学習の方は下がり、ランダム初期化の方は上がります。epoch 24 以降は、両者の差が clean 1.3pt、PGD-10 0.3pt 以内に収まります。
3. **lr 0.05 の 40 epoch はほぼ横ばいです。** val PGD-10 は 18.9〜20.5% の間にとどまります。伸びのほとんどは 2 回の LR 減衰で生まれます（epoch 50 で +6.7pt、epoch 76 で +2.6pt）。
4. **学習画像でも頑健性はまだ低いです。** 学習画像の probe で測った PGD-10 は約 35% です。このモデル規模では、過学習よりも学習不足が支配的な状態が続いています。

## ノイズの大きさ

CIFAR で同じ設定を 2 回走らせたときの差は 0.16〜1.88pt でした。乱数だけで 1〜2pt 動く、というのがこのプロジェクトの目安です。
Arm A の 2 seed の差は PGD-10 で 0.01pt でした。ただし 2 本だけではばらつきの推定になりません。
今回の差（0.1〜0.35pt）は、このノイズの範囲に入ります。したがって「事前学習が効く」とも「100 epoch が効く」とも言えません。
言えるのは「1pt を超える効果は、この seed では見えなかった」ということだけです。
今回の 2 本をそれぞれもう 1 seed 増やしても、0.3pt 程度の差は判定できません。そのためその案は選択肢から外しました。

## 費用の前提

実測では、100 epoch に Hamster の 4090 で約 44.5 時間かかりました（2026-09-23 16:04 から 09-25 12:37 UTC）。
epoch 1〜4 は co-location で遅くなっていたので、1 epoch あたり約 0.42〜0.45 時間と見積もります。
よって MobileNetV4-S の 50 epoch は 1 本あたり約 20〜25 GPU-h です。
いま Hamster の 2 枚は空いています。

## A：2x2 を閉じて、Phase 1 を Arm A のレシピで始める

- **GPU 時間**：この判断には 0 h。Phase 1 自体の費用は別に計算します。
  他のアーキテクチャは MobileNetV4-S より遅く、1 本あたりのコストはそのぶん上がります。
- **確定すること**：Phase 1 は事前学習済み初期化・50 epoch で行います。
  MobileNetV4-S では、倍の予算にもランダム初期化にも、1pt を超える差は見えませんでした。
  それなら安い方（50 epoch）で十分です。
- **判定ルール**：新しいジョブは走らせないので、ルールは不要です。
- **リスク**：「事前学習の有利さは 100 epoch で消える」という結果は、MobileNetV4-S・seed 1 本だけのものです。
  他のアーキテクチャ（特に DeiT-Tiny のような ViT）では事前学習がもっと効くかもしれません。
  Singh et al. は ViT-S で +7.3pt AutoAttack と報告しています。
  ただし Phase 1 はどのモデルも事前学習済みから始めるので、この結果とは食い違いません。

## B：ランダム初期化・50 epoch のセルを埋める

- **GPU 時間**：約 20〜25 GPU-h（4090 1 枚、seed 0）。
- **確定すること**：同じ 50 epoch の予算で事前学習が効くかどうか。
  論文で「事前学習済みからの fine-tuning」を主張する場合、同じ予算での対照になります。
- **判定ルール（事前登録）**：ランダム初期化・50 epoch の last PGD-10 を見ます。
  Arm A の低い方の値（30.58%）より 1pt 以上低ければ（29.58% 以下）、「50 epoch では事前学習が効く（n=1）」とします。
  それ以外なら「50 epoch でも 1pt を超える差は見えない」とします。clean も並べて報告します。
- **リスク**：結果の予想は立ちます。ランダム初期化・100 epoch の run は epoch 24 で 37.12/19.51 でした。事前学習の方は 38.38/19.58 です。
  50 epoch 版では lr 0.05 の区間が 15 epoch に縮まるので、clean が 1pt ほど下がる可能性はあります。
  ただ、PGD-10 で 1pt を超えるかどうかははっきりしません。
  どちらの結果でも Phase 1 のレシピは変わりません。変わるのは論文の主張の範囲だけです。

## C：LR スケジュールを見直す新しい plan

- **GPU 時間**：1 本あたり約 20〜25 GPU-h。まずは 1 通りのスケジュール × seed 0 で行います。
- **確定すること**：lr 0.05 の区間を短くすると（例：最初の減衰を epoch 25 より前にする）、同じ 50 epoch で頑健性が上がるか。
- **判定ルール（事前登録）**：同じ 50 epoch・同じ攻撃で比べます。last PGD-10 が Arm A の高い方（30.59%）より 1pt 以上高ければ（31.59% 以上）、新しいスケジュールを Phase 1 に採用する候補にします。
  それ以外なら Arm A のままにします。
- **リスク**：スケジュールの変更は新しい科学的契約です。新しい plan と protocol id が必要です。
  Phase 1 の開始は少なくとも 1 日遅れます。
  もし採用すると、Arm A の 2 seed や 2x2 の結果とは直接比べられなくなります。
  Phase 0 の結論（「頑健性を伸ばすのは容量と学習誤差」）から見ても、スケジュールは主役ではありません。

## 推奨

**A** を推奨します。
2x2 の目的は「Phase 1 をどの予算と初期化で行うか」を決めることでした。その答えは出ています。
MobileNetV4-S では、倍の予算にも初期化の違いにも 1pt を超える効果が見えませんでした。
それなら安い 50 epoch・事前学習済みで比べるのが筋です。
Hamster の 2 枚は空いています。すでに承認済みの 2 件（EasyRobust の外部アンカー評価と、4090 での throughput 調査）もこの GPU を待っています。

判断が変わるのは次の場合です。
- 論文の中心に「同じ予算でランダム初期化と比べて、事前学習が効く」という主張を置きたい場合は、**B** が必要です。
  B は 4090 1 枚で約 1 日なので、Phase 1 と並行して走らせることもできます。
- lr 0.05 区間の横ばいを、方法論上の結果として追いたい場合は、**C** を別の plan として立ててください。
