- **Phase 2 のルール**（1.5pt 以上「効果あり」、0.5〜1.5pt「保留」、0.5pt 未満「効果なし」）で見ると、PGD-10 の大きさは「保留」の帯（1.5 まで 0.11pt、約 28 枚）ですが、**向きは下がる側**です。clean は 1.5pt を越えて下がっています。
  この arm には、別の事前ルールを書いた packet はありません（discussion register B、2026-10-08 の⑤「ConvNeXt の深さと幅」として承認された候補です）。

## 選択肢

### A: 記録だけで閉じる（おすすめ）

- **GPU時間**: 0。
- **わかること**: 新しいことはありません。「計算量をそろえて深く細くすると、seed 0 で PGD-10 −1.39 / clean −1.72、当てはまりも下がる」と記録します。
- **事前ルール**: Phase 2 のルールの「保留」は「2本目の seed で確かめる」ですが、このルールは改善を確かめるためのものです。下がる側の結果は、2本目でどう出ても採用にはつながらないので、この packet の判断として「改善なし、閉じる」と記録します。ConvNeXt-Atto の形は標準（2,2,6,2）/（40..320）のままにします。深さを改めて問う場合は、新しい計画と packet で決めます。
- **リスク**: 本当の差が −0.5pt 程度（「効果なし」）だったとしても、それを「下がる」と書いてしまう可能性があります。論文に書くときは「seed 1本で下がった」とだけ書きます。

### B: 深く細い版の seed 1 を回す

- **GPU時間**: 約 29〜31 時間（この run の実測 29.40 時間、Hamster の 4090 1枚）。Ferret では基準＋EMA が標準の Atto で 1.2 倍ほど遅かったので、Ferret なら 約 35〜40 時間の見込みです。
- **やり方**: `imagenet_convnext_atto_deep_narrow_pgd_at_phase2_adamw_random_lr1em3.yaml` を seed 1 で、seed 0 と同じ `5dd329e` の worktree から回します。比べる相手は既にある Phase 1 の ConvNeXt-Atto lr 1e-3 seed 1（Ferret で実行済み）。その clean / PGD-10 は、run の前に Ferret の bundle から読んで plan に書き写します。
- **わかること**: seed 1 でも下がるか。
- **事前ルール**: d1 = 深く細い版 seed 1 − Phase 1 seed 1（最後の普通の重み、取り分けた画像すべての PGD-10）。d1 ≤ −0.5pt → 「2本とも下がる」として閉じる。−0.5 < d1 < +0.5 → 「効果なし」として閉じる。d1 ≥ +0.5 → seed 0 と向きが逆なので「判定できない」と記録し、追加するかは改めて packet で決める。2本の平均やばらつきは出しません。
- **リスク**: Phase 1 seed 1 は EMA なしの設定・別の source・Ferret で、設定の違いが混ざります。どの結果でも「採用」にはつながらないので、30 時間を採用判断に効かない確認に使うことになります。

### C: パラメータ数をそろえた深い版を、新しい計画として立てる

- **GPU時間**: 実装とレビューのあと、約 35〜45 時間（見積もり。ブロック数 (3,3,8,1) のまま幅を約 1.16 倍にするとパラメータは標準の Atto（3.70M）と同じくらいになり、計算量は約 1.3 倍、速さはこの run の 610 枚/秒から約 450 枚/秒に落ちると仮定）。
- **わかること**: パラメータ数が同じなら、深い形が効くか。今回の結果が「パラメータが減ったせい」か「形のせい」かを分ける一歩になります。
- **事前ルール**: 新しいモデル id と設定を作るので、新しい計画（plan）と科学レビューが要ります。判定は基準＋EMA（59.69 / 36.92）との差に Phase 2 のルール（≥1.5pt「効果あり」、0.5〜1.5pt「保留」、<0.5pt「効果なし」）。計算量 +約 30% を結果と必ず並べて書き、「計算量をそろえた比較ではない」と明記します。
- **リスク**: 計算量が増えるので、軽量モデルの比較としては公平でなくなります。上がっても「計算を増やしたから」と区別できません。軽量モデルの研究としての価値は低めです。

## おすすめ: A

下がり幅（PGD-10 −1.39、clean −1.72）は seed の差（0.36pt）の約 4 倍で、学習の最初から最後まで同じ向きに続き、学習データへの当てはまりの低下という筋の通った理由もあります。
B の seed 1 は「下がる」か「効果なし」かを分けるだけで、どちらでも深く細い形を採用することにはなりません。
C は計算量が増えるため、軽量モデルを同じ計算量で比べるというこの研究の比べ方から外れます。
2026-10-13 の方針（学習不足を補う方向）からも、パラメータを減らす変更を追う理由は弱いです。GPU は蒸留の検証（2026-10-14 の決定）や、効果が「保留」以上で上がる向きの問い（0052/0053 の cosine、0054 の 100 epoch）に回すほうが得るものが大きいと考えます。

**判断が変わる場合**:
- 論文の表に「深さと幅」の行を seed 2本でそろえて載せたい場合 → B。
- 「パラメータか形か」を論文の主張として切り分けたい場合 → C（新しい計画として）。
- 走っている ConvStem 版が大きく上がり、ConvNeXt-Atto の形の改良を論文の柱にする場合 → C を改めて検討する価値が上がります。
