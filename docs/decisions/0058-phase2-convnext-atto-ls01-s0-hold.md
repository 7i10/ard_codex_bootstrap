- **基準＋EMA との差: clean −0.06 / PGD-10 +0.69**（25,620 枚のうち約 176 枚）。取り分けた画像の残り 20,620 枚でも −0.15 / +0.67、EMA の重みでも −0.08 / +0.76 で、同じ向きです。
- **Phase 2 のルール**（1.5pt 以上「効果あり」、0.5〜1.5pt「保留」、0.5pt 未満「効果なし」）では、PGD-10 は **「保留」**（「効果なし」との境界から 0.19pt、約 49 枚上）、clean は「効果なし」です。
  この arm には、別の事前ルールを書いた packet はありません（discussion register B、2026-10-08 の④として承認された候補です）。
- **MobileNetV4-S でも同じ向きでした。** MobileNetV4-S のラベル平滑化は clean −0.50 / PGD-10 +0.45（decision 0039、ルールでは境界の 0.05pt 下で「効果なし」）。ConvNeXt-Atto は clean をほとんど落とさずに +0.69 です。どちらも seed 1本で、最適化手法（SGD と AdamW）なども違います。
- **cosine には届いていません**（−1.07 / −0.29。こちらは source とホストも違う参考の比較）。cosine とラベル平滑化を同時に使った run はまだありません。
- **差が出る時期**: 5,000 枚のサブセットの PGD-10 は、epoch 0 では同じ（−0.06）、ウォームアップの終わりで +0.70、ピーク LR の間は上下（epoch 24 で −0.34）、最初の LR 低下（epoch 25）からは表にしたすべての epoch で上（+0.50〜+1.14、最後 +0.78）です。clean は全体を通して ±0.8pt の中です。サブセット1行ごとの差は誤差（約 0.9pt）の中ですが、後半 25 epoch ずっと同じ向きで、全体の評価とも合っています。
- **学習画像と見ていない画像の差が PGD-10 で縮みました**（+6.28 → +5.19）。誤差（約 1.1pt）の中ですが、ラベル平滑化が学習画像への合わせすぎを抑えるなら、こう出るはずの向きです。
- EMA は最後には効いていません（+0.01 / +0.14）。頑健さの過学習なし（best = 最後）。学習崩壊の見張りは一度も発動していません（サブセットの最大の落ち込み 0.64pt）。
- 実時間 46.92 時間（基準＋EMA 32.18 時間）。Ferret の相乗りで遅い時期（241〜362 枚/秒）があり、後半は 514〜536 枚/秒でした。ラベル平滑化そのものは計算をほとんど増やしません。

**ばらつきの目安（noise floor）**: ImageNet では seed 0 と seed 1 の差が MobileNetV4-S 0.36pt、MobileNetV4-M 0.09pt、ConvNeXt-Atto 0.36pt でした（各1組）。2本の全体評価の差の SE は PGD-10 で約 0.37pt、clean で約 0.43pt です。CIFAR の画面では seed だけで 1〜2pt 動くことがありました。

**注意: PGD だけの評価です。** ラベル平滑化は、出力の自信を下げることで PGD の勾配を弱め、実際より頑健に見せることがある（勾配の隠れ、gradient masking）と知られています。今回の +0.69 がそれかどうかは、もっと強い攻撃（AutoAttack）でしか確かめられません。

## 選択肢

### A: ラベル平滑化の seed 1 を回す

- **GPU時間**: 約 25〜27 時間（Hamster の 4090 1枚。標準の Atto の cosine を Hamster で回したときの 713〜716 枚/秒と、1 epoch あたり約 65 秒の検証などを足して見積もり）。Ferret は相乗りで短い job 向きなので使いません（Ferret なら今回の実測で 32〜47 時間）。
- **やり方**: `imagenet_convnext_atto_pgd_at_phase2_ls01.yaml` を seed 1 で、seed 0 と同じ `9a16cd6` の worktree から回します。比べる相手は既にある Phase 1 の ConvNeXt-Atto lr 1e-3 seed 1（Ferret で実行済み）。その clean / PGD-10 は、run の前に bundle から読んで plan に書き写します。0053 の A（cosine seed 1）も同じ相手と比べるので、両方を選ぶなら比べ方がそろいます。
- **わかること**: seed 1 でも上がるか。
- **事前ルール**: d1 = ラベル平滑化 seed 1 − Phase 1 seed 1（最後の普通の重み、取り分けた画像すべての PGD-10）。d1 ≥ +0.5pt → 「2本とも上がる」として、Phase 2 の候補を組み合わせるときの候補に残す（採用そのものは改めて決める）。−0.5 < d1 < +0.5 → 「効果なし」で閉じる。d1 ≤ −0.5 → seed 0 と向きが逆なので「判定できない」と記録し、追加するかは改めて packet で決める。2本の平均やばらつきは出しません。
- **リスク**: Phase 1 seed 1 は EMA なしの設定・別の source で、Phase 2 の共通設定の違いが混ざります（基準＋EMA の設定チェックでは −0.10pt でした）。2本そろっても、差が 0.5〜0.7pt 程度なら CIFAR の目安より小さいままです。AutoAttack の問題（勾配の隠れ）は残ります。

### B: いまは何も足さない（おすすめ）

- **GPU時間**: 0。
- **わかること**: 新しいことはありません。「ConvNeXt-Atto でラベル平滑化 0.1 は seed 0 で PGD-10 +0.69、clean −0.06、保留」と記録します。
- **事前ルール**: ラベル平滑化は採用も却下もしない「保留」のままにします。cosine の判断（0052 / 0053）が出て、Phase 2 の候補を組み合わせる計画を立てるときに、この packet を開き直し、そのときに A か C を選ぶかを決めます。それまでに MobileNetV4-S（0039）が「効果なし」で閉じても、この packet の判定は変えません（モデルが違うため）。
- **リスク**: 決定が先に延びます。組み合わせの計画を立てるときには、cosine の seed 1 と合わせて回す本数が増える可能性があります。

### C: AutoAttack で勾配の隠れを先に確かめる

- **GPU時間**: 約 2〜6 時間（見積もり。この計画ではまだ AutoAttack を ImageNet で回したことがなく、実測がありません。ConvNeXt-Atto は軽いので、5,000 枚・チェックポイント2つで、1つあたり 1〜3 時間と仮定）。
- **やり方**: 基準＋EMA とラベル平滑化の `last.pt`（最後の普通の重み）に、標準の AutoAttack（l_inf 4/255）を、保存済みチェックポイントから別プロセスで `--allow-autoattack` を付けてかけます。画像はどちらも同じ 5,000 枚で、checkpoint の選択に使ったサブセットとは別の、取り分けた画像の残り（complement）から決まった手順で選びます。この選び方と評価の手順は plan に追記してレビューを通してから回します（Phase 2 の評価を変えるのではなく、評価を足すだけです）。
- **わかること**: PGD-10 の +0.69 が、強い攻撃でも残るか。
- **事前ルール**: 同じ 5,000 枚での AutoAttack 精度の差 g = ラベル平滑化 − 基準＋EMA。g ≥ +0.5pt → 「PGD の上げ幅は勾配の隠れではない」として記録し、A を選ぶ根拠にする。g < +0.5pt で、同じ 5,000 枚の PGD-10 の差が +0.5pt 以上 → 「PGD の上げ幅は AutoAttack では確かめられない」と記録し、ラベル平滑化は閉じる側に倒す。5,000 枚の差の SE は約 1.0pt なので、g はあくまで向きの確認です。
- **リスク**: 5,000 枚では差の SE が約 1.0pt あり、+0.5pt の判定は誤差の中です。評価の手順を新しく足すので、plan の追記とレビューの手間がかかります。どちらの結果でも seed は1本のままです。

## おすすめ: B

+0.69 は「保留」の帯の下の方で、seed の差の約 2 倍、CIFAR の目安より小さい値です。clean の損がない点と、MobileNetV4-S でも同じ向きだった点は前向きな材料です。
ただし、GPU は蒸留の検証を優先しており、cosine の seed 1（0052 / 0053）もまだ決まっていません。ラベル平滑化を最終的に入れるかどうかは、cosine と組み合わせたときに効くかで決まるので、その計画を立てるときにまとめて判断するのが無駄が少ないと考えます。
いま 25〜27 時間を使っても、2本目が +0.5pt 前後なら判定は誤差の中にとどまり、AutoAttack の問題も残ります。

**判断が変わる場合**:
- 0053 で A（cosine seed 1）を選ぶ場合 → 同じ比べ方になるので、この packet の A を同時に選ぶ価値が上がります。
- 論文の表に「ラベル平滑化」の行を載せる予定がある場合 → まず C（安い、勾配の隠れの確認）、それで残れば A。
- 「1000 クラスで 0.1 は適切か」という疑問を確かめたい場合 → この packet の範囲外です。別の値（例: 0.05、0.2）を試すのは新しい計画として立てます。
