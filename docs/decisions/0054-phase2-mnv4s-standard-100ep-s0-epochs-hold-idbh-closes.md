## 選択肢

### A: IDBH を閉じ、100 epoch は記録だけ

- **GPU時間**: 0。
- **わかること**: 新しいことはありません。IDBH の線を 0046 B のルールで閉じ、epoch 倍の +1.17 を「保留（seed 1本）」として記録します。
- **事前ルール**: 0046 B のとおり（上のまとめ）。100 epoch を使うかどうかは、最終レシピを固める段階で、ほかの要素（SiLU、cosine など）とまとめて確かめます（weight decay 除外を 2026-10-13 B で同じ扱いにしたのと同じ）。
- **リスク**: Phase 2 のルールでは「保留」は2本目の seed で確かめることになっています。それをしないまま、100 epoch の扱いを後回しにします。最終レシピで 100 epoch を使うなら、そのとき1本ずつの学習の費用が2倍になります。

### B: A ＋ 標準拡張 × 100 epoch の seed 1（おすすめ）

- **GPU時間**: 約 31〜33 時間（Hamster の 4090 1枚、決定的＋CUDA Graphs。IDBH × 100 の Hamster GPU1 での実測 30.82 時間から）。Ferret で回すと今回のように 35〜39 時間かかることがあります。
- **わかること**: epoch を倍にした +1.17 が seed 0 だけのものか。config は今回と同じ（`imagenet_mobilenetv4_pgd_at_random_init_lr0025_100ep_cg.yaml`、`5dd329e`）で、seed だけを 1 にします。
- **事前ルール**（seed 1 の最後の普通の重み、取り分けた画像すべての PGD-10 を、基準 30.71 と比べる。0044 C と同じ形）:
  - +1.5pt 以上（32.21 以上）→ seed 1 は「効果あり」。seed 0 の「保留」と合わせて「100 epoch は PGD-10 を上げる（この2本について）」と記録し、Phase 2 の比較を 100 epoch でするかは別の packet で決める。
  - +0.5〜1.5pt（31.21〜32.21）→ 「2本とも同じ向き（この2本について）」と記録し、同じく別の packet。
  - +0.5pt 未満（31.21 未満）→ 「epoch 倍の効果は seed 1 で再現しない」と記録し、100 epoch は Phase 2 の標準にしない。
  - clean も並べて報告します（判定は PGD-10 だけ）。
- **リスク**: 基準 30.71 は seed 0 の 50 epoch です。seed 1 の 50 epoch の値（Phase 1 では seed の差 0.36pt）とは比べないので、seed の揺れが 0.36pt ほど判定に混ざります。約 31 時間を使って、答えは「この2本について」の向きだけです。

### C: A ＋ SiLU × 100 epoch

- **GPU時間**: 約 38〜41 時間（Hamster の 4090 1枚。SiLU 50 epoch の実測 928〜943 枚/秒から、100 epoch で学習 約 37 時間＋評価など）。
- **わかること**: epoch を倍にした効果が、今いちばん良い SiLU（33.27）の上にも乗るか。学習不足を補う2つの手段が足し算になるかどうかで、最終レシピの形に直接つながります。
- **事前ルール**: SiLU × 100 − SiLU × 50（33.27、同じ `5dd329e`）の PGD-10 に Phase 2 のルール（1.5pt 以上「効果あり」、0.5〜1.5pt「保留」、0.5pt 未満「効果なし」）。あわせて、足し算の見込み（33.27 + 1.17 = 34.44）との差を報告します（判定には使いません）。
- **リスク**: SiLU × 100 の config はまだ無く、新しい条件として plan への追記と config のレビューが先に要ります（epoch 数と milestones だけを今回の run と同じに変えるもの）。seed 0 の1本なので、「保留」に入れば結局 seed が要ります。標準拡張の +1.17 が seed で再現するかは、これではわかりません。

## おすすめ: B

Phase 2 のルールは、0.5〜1.5pt の「保留」を2本目の seed で確かめると決めています。+1.17 はその幅の中なので、ルールどおりなら B です。
100 epoch は1本ごとの費用を2倍にする選択なので、標準にするかを決める前に、seed 0 だけの結果でないことを確かめる価値があります。今回の4つの候補（100 epoch、TRADES、AWP、IDBH）で clean と PGD-10 の両方を上げたのはこれだけで、人間の方針（学習不足を補う）にも合っています。
A は費用 0 ですが、ルールの「保留」を確かめないまま残します。C は最終レシピに近い問いに答えますが、標準拡張の +1.17 の再現性はわからないままです。

**判断が変わる場合**:
- 最終レシピを SiLU で組むことが決まっていて、ReLU の結果を固める必要がない → C。
- Hamster のキューに優先する run があり、31 時間を空けられない → A（最終レシピの段階で確かめる）。
- 0042 の B で `5dd329e` が `d836c03` と一致しなかった → epoch 倍の +1.17 の読み方が変わるので、先に 0042 B（1時間足らず）を済ませてから選び直す。B の seed 1 は、同じ `5dd329e` のまま回すので、比較の相手（30.71、`d836c03`）との source の違いが残ります。
