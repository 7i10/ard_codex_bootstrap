# 0047: Phase 2 の TRADES β=6、MobileNetV4-S seed 0 が完了（clean +0.64、PGD-10 −4.65）

## 結果のまとめ

記録: `docs/plans/0103-lightweight-imagenet-architecture-survey.md` の Progress log、2026-10-13 (postrun, Phase 2 TRADES beta 6)。
証拠台帳 `docs/RESEARCH_STATUS_SUMMARY.md` の最後の行。結果のコミットは `078d5a4`。
この契約には集計スクリプトが無いので、`docs/experiments/` の record はありません（数字は `epoch-metrics.jsonl` と run-bundle の manifest から読みました）。

TRADES は、きれいな画像の CE と「攻撃した画像の出力ときれいな画像の出力の KL」を β=6 の重みで足した損失で学習します。
学習時の攻撃は、CE ではなく KL を大きくする方向に 3 step（l_inf 4/255、step 8/765、ランダムスタート）動かします。
評価はほかの Phase 2 の run と同じ CE の PGD-10 です。
それ以外は基準＋EMA と同じレシピです（50 epoch、224 px、SGD lr 0.025、LR は epoch 25 と 38 で下げる、weight decay 1e-4 を全パラメータに、標準の拡張、Phase 2 のテンプレート）。

条件: ImageNet-1k（元画像）、MobileNetV4-S（ReLU）、ランダム初期化、教師なし、seed 0、world size 1、バッチ 128、決定的モード、eager（CUDA Graphs は `pgd_at` 以外では使えない）。
数字はすべて内部検証（学習データから取り分けた 25,620 枚）で、公式テストではありません。AutoAttack も公式評価もまだです。

- **基準と比べると clean +0.64、PGD-10 −4.65。** 2本の差の誤差（SE）は clean 約 0.43pt、PGD-10 約 0.37pt なので、PGD-10 の差は約 12 SE、clean は約 1.5 SE です。EMA の重み同士では +1.05 / −4.34。
- **Phase 2 のルール**（1.5pt 以上で「効果あり」、0.5〜1.5pt で「保留」、0.5pt 未満で「効果なし」）では、大きさは「効果あり」の段で、向きは損です。
- **差は warmup の終わりからあり、だんだん広がります。** サブセットの PGD-10 の差は epoch 9 で −2.38、24 で −3.40、37 で −4.12、49 で −4.52。clean は逆にずっと上です（epoch 9 で +4.98、49 で +0.98）。
- **学習に使った画像でも同じだけ低いので、汎化の問題ではなく「頑健さを学びきれていない」問題です。** 学習画像 2,000 枚（拡張なし）での PGD-10 は 28.80 で、基準の 34.40 より 5.60 低い。学習画像と取り分けた画像の差は、TRADES のほうがむしろ小さい（+2.74、基準 +3.69）。
- **学習時の KL 攻撃は、ラベルを外させる力が弱いようです。** KL 攻撃をかけた学習バッチでは 45.85% が正解のまま残ります。同じ頃、学習画像に CE の PGD-10 をかけると 28.80% しか残りません。基準では逆で、学習中の CE PGD-3 で 27.90%、PGD-10 で 34.40% です。モデルは「出力の分布を動かす」攻撃には耐えるよう学んでいますが、「ラベルを変える」攻撃への耐性は少ししか身についていない、と読めます。ただし原因として確かめたわけではありません。
- 頑健性の過学習は無し（best − 最後 = −0.03pt）。崩壊の見張りは一度も作動していません（サブセットの最大の落ち込みは 0.92pt）。
- 時間: 22.28 時間（基準＋EMA の 1.44 倍）、800〜829 枚/秒（eager）。

**注意点**: seed は1つだけ。source（`5dd329e` と `d836c03`）と実行モード（eager と CUDA Graphs）が基準と違い、どちらの影響も切り分けていません（source の確認は 0042 B として保留中）。
ただ、同じ `5dd329e` から回したほかの run（SiLU、weight decay の除外、IDBH）の基準との差は −1.42〜+2.56pt で、4.65pt の損はそれより外にあります。
読んだのは β=6・KL 3 step の1点だけです。TRADES の元の論文の設定（CIFAR で KL 10 step）は、この規模では再現していません。

## 揺れの大きさ（ノイズの床）

MobileNetV4-S の seed 0 と seed 1 の差は 0.36pt、full val で2本を比べた差の SE は PGD-10 で約 0.37pt です（plan 0103、2026-10-11 の記録）。
今回の −4.65pt はこの床の 12 倍以上あり、seed 1 を回しても向きは変わらないと見込めます。
そのため seed 1 は選択肢に入れていません。
B と C は、基準を 1.5pt 以上（Phase 2 の「効果あり」）上回るかどうかで判定するので、床より十分大きい差だけを読みます。

## 選択肢

### A: ここで閉じる

- **GPU 時間**: 0。
- **分かること**: 「MobileNetV4-S では、TRADES β=6（KL 3 step）は PGD-AT の基準より CE PGD-10 で 4.65pt 低い」と記録して TRADES の線を閉じます。TRADES の他の run はキューに入れません。Hamster の空きは残りの Phase 2 の候補（AWP、蒸留など）に回せます。
- **事前に決めた判定**: なし（判定をしない選択肢です）。
- **リスク**: β と攻撃の step 数のどちらが原因かは分からないままです。論文で「TRADES は PGD-AT と同じくらい頑健」とされる結果が、小さいモデル・ImageNet・短い攻撃の組み合わせで崩れるのか、という問い自体は開いたまま残ります。

### B: β=12 の TRADES を1本だけ回す

- **GPU 時間**: 約 22〜24 時間（今回の 22.28 時間を基準に。β を変えても計算量は同じ）。Hamster 1枚。
- **分かること**: 頑健性の項の重みを倍にすると、PGD-10 の損が埋まるかどうか。β を上げると clean は下がり、頑健性は上がる方向に動くのが普通です。
- **事前に決めた判定**: 最後の普通の重みで full val PGD-10 が **32.21 以上**（基準 30.71 + 1.5）なら TRADES の線を続ける。30.71〜32.21 なら「基準と同等で、clean を見て判断」として人間に返す。30.71 未満なら閉じる。
- **リスク**: 4.65pt を埋めて、さらに 1.5pt 上回るのは見込みが低い。原因が「KL 攻撃が弱い」ことなら、β を上げても弱い攻撃への耐性を強めるだけで、CE PGD-10 は大きく動かない可能性があります。β はメソッドの係数で、ε・step 数・評価の攻撃は変えません。

### C: 学習時の KL 攻撃を 10 step にした TRADES β=6 を1本回す

- **GPU 時間**: 約 45〜60 時間（今回 3 step で 815 枚/秒前後。1 step あたりの順伝播＋逆伝播の数から、10 step では 300〜400 枚/秒と見積もり）。Hamster 1枚。
- **分かること**: KL 攻撃の弱さ（上の読み）が原因かどうか。元論文の CIFAR の設定に近づけた TRADES が、この規模で PGD-AT に追いつくか。
- **事前に決めた判定**: 最後の普通の重みで full val PGD-10 が **32.21 以上**なら続ける（ただし基準の PGD-3 より攻撃にかける計算が約 3 倍あることを併記する）。30.71〜32.21 は人間に返す。30.71 未満なら閉じる。
- **リスク**: 学習時の攻撃の step 数を変えるので、**新しい科学契約**です。別の plan とレビューが必要です。また、基準（PGD-3）と攻撃の計算量がそろわないので、勝っても「TRADES が良い」のか「攻撃に計算をかけたから良い」のかが分かれません。公平にするには PGD-10 で学習した基準も要り、さらに約 40〜50 時間かかります。

## おすすめ: A

−4.65pt はノイズの床の 12 倍以上で、Phase 2 のルールでもはっきりした損です。
B は「β を倍にして 6pt 以上動く」ことが必要で、見込みが低いわりに 1 日分の GPU を使います。
C は原因を確かめる意味はありますが、新しい契約と公平な基準のための追加 run が要り、Phase 2 の目的（同じ計算量で基準を超える工夫を探す）から外れます。
2026-10-12 の判断（混ぜる方式の線を閉じたとき）でも、clean を上げる手段の候補に TRADES が挙がっていました。
今回 clean は +0.64（約 1.5 SE）しか上がっておらず、その役目も十分には果たしていません。

**判断が変わる条件**: 研究の問いとして「TRADES が小さいモデルの ImageNet で崩れる理由」を論文の一部にしたい場合は、C（と PGD-10 で学習した基準）に意味が出ます。
また、0042 B（source の確認）で `5dd329e` 自体が基準より 2pt 以上低いと分かった場合は、今回の差の一部が source のせいになるので、この判断を見直します。
