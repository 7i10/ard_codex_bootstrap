## ノイズの目安

- 1つの数字の SE は PGD-10 で約 0.28pt、2本の差の SE は約 0.40pt です。基準との差 −2.52pt はその約6.3倍です。
- ImageNet での seed による揺れは、Arm A の seed 0 と 1 の1組（PGD-10 の差 0.01pt）しか測っていません。1組では揺れの幅は分かりません。
- CIFAR では対照同士で 0.16〜1.88pt 動いた例があります。基準との差（2本とも −2.26〜−2.52pt）はこれを超えます。
  from100 と from195 の差（−0.26pt）はこれより小さく、差が無いとも有るとも言えません。
- したがって「この seed・この stage 2 の設定では、stage 1 の長さによらず悪い」とは言えますが、「2段階学習という方法は悪い」とは言えません。

## 選択肢

### A: Ferret の2本を待って閉じる（0028 の A）

- **内容**: 新しい run は入れない。Ferret の2本の postrun を順に行い、4本すべてに同じ事前登録ルールを当てて閉じる。
- **GPU時間**: 追加 0。ただし共有ホストの Ferret を2本が使い続けます（残り時間は未確認）。
- **分かること**: stage 1 が 50 epoch でも結論が同じか。S=256 か元画像かで stage 2 の後に差が出るか。
- **事前登録ルール**: 各 stage 2 の最後の epoch の PGD-10 を 30.71 と比べる（+1pt 以上=良い、±1pt=同等、−1pt 以下=悪い）。
  4本すべて「悪い」なら、2段階学習は今の設定では採らず、フル AT 50 epoch を Phase 1 の基本とする。
  どれか1本でも「同等」以上なら、その1本について seed を足すかを新しい packet で決める。
- **リスク**: 得られる情報が少ないわりに Ferret を長く使います。stage 1 の終わりの値（50 epoch は 20.44 / 20.58%、195 は 21.11%）と今回の2本から見て、2本とも「悪い」になる見込みが高いです（予想であって結果ではありません）。

### B: Ferret の2本を止めて今閉じる（推奨。0028 の C）

- **内容**: from50s256 / from50orig を今止め、ABANDONED と記録する。Hamster の2本（どちらも「悪い」）で2段階学習パイロットを閉じ、plan に閉じた理由を書く。
- **GPU時間**: 追加 0。Ferret の2本分の残り時間を節約し、共有ホストを空けます。
- **分かること**: 今の stage 2 の設定では、stage 1 が 195 でも 100 epoch でも単一段階より低い、で閉じます。S=256 対 元画像の問いは「2段階学習を採らないので不要」として閉じます。
- **事前登録ルール**: 0028 の C で書いたルール「from100 も『悪い』（29.71% 未満）なら閉じる」がそのまま当たります（28.19%、best でも 28.40%）。
  閉じた後は、フル AT 50 epoch を Phase 1 の基本とします。
- **リスク**: Ferret の操作（run-on-ferret での停止）が要ります。もし2本がほぼ終わっていれば、止めて得るものは小さく、A と差がありません。
  50 epoch 版がたまたま良かった、という可能性は確かめられなくなります（上の理由で低いと見ています）。

### C: 閉じる前に stage 2 の lr を 0.025 にした1本を足す（0028 の B を from100 から）

- **内容**: 100 epoch 版の last.pt から、lr 0.025、ほかは同じ（20 epoch、2 epoch ウォームアップ、epoch 10 と 15 で 1/10）の stage 2 を Hamster で回す。
  195 と 100 で差が無かったので、安い方の 100 epoch 版を土台にします。スケジュールの変更なので、**新しい科学的条件**として plan への追記と config のレビューが先に要ります。
  A か B と組み合わせられます。
- **GPU時間**: 約 7.5〜8.5 GPU時間。config 作成とテストに少し。
- **分かること**: stage 2 で PGD-10 が伸びなかったのが、stage 2 の lr が低すぎたせいかどうか。
- **事前登録ルール**: 最後の epoch の PGD-10 を 30.71 と比べる（±1pt、上と同じ）。さらに今回の 28.19 より 1pt 以上高ければ「stage 2 の lr が効く」と書く。
  ±1pt 以内なら「lr を10倍にしても変わらない」として2段階学習を閉じる。
- **リスク**: 結果を見てから条件を変える「救済」の試みで、1 seed では当たっても解釈が弱いです。
  AdvXL も stage 2 は低めの lr の微調整なので、今の lr の選び方が不自然だったわけではありません。
  lr を上げて stage 1 の重みを大きく動かすなら、2段階学習の「低解像度で安く学ぶ」意味が薄れます。Phase 1 の本線（学習率グリッド）から Hamster の GPU を取ります。

## 推奨

B を勧めます。0028 の時点では from100 の結果を待つ理由がありましたが、今は2本とも事前登録ルールで明確に「悪い」（−2.26 / −2.52pt）で、
どの epoch を取っても変わらず、stage 1 の長さによる差も見えません。Ferret の2本が答える問いは、
stage 1 の長さ（すでに答えが出た）と S=256 対 元画像（2段階学習を採らないなら不要）で、残りの情報価値は小さいです。
Ferret は共有ホストなので、長い run を早く空ける価値があります。
推奨が変わるのは次の場合です。Ferret の2本がもうほぼ終わっている場合（そのときは A で待つのと差が無いので A）、
または、人間が「stage 2 の lr を1点しか試していないので、閉じる前に1回は lr を上げて確かめたい」と判断した場合（そのときは C を A か B に足す）です。
