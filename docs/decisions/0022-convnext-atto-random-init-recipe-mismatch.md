わかったこと：
1. **ConvNeXt-Atto は MobileNetV4-S より大きく劣ります。** パラメータ数はほぼ同じ（3.70M 対 3.77M）で計算量は約 3 倍なのに、clean で −23.2pt、PGD-10 で −14.2pt です。ノイズ（1〜2pt）の 7 倍以上の差です。
2. **最初から学習が遅いです。** warmup が終わった epoch 9 で val clean は 8.86% しかありません。同じ LR の MobileNetV4-S は epoch 24 で 41.59 / 22.29 でしたが、ConvNeXt-Atto は 21.95 / 12.17 です。
3. **ピーク LR の区間は頭打ちになる前に終わりました。** epoch 9〜24 で val PGD-10 は 4.86% から 12.17% まで伸び、最後の 5 epoch でも 1 epoch に約 0.3pt ずつ伸びていました。最初の LR 減衰では 1 epoch で PGD-10 +2.31pt、clean +5.03pt 伸びました。後の 2 つの区間は平らになっています（epoch 44〜49 で 16.34〜16.59%）。
4. **学習画像でも同じくらい当たりません。** 最後の epoch の probe − val は clean +0.77、PGD-10 −0.93 で、probe の誤差（約 1.0 / 0.8pt）の範囲です。学習した画像にもまったく合わせられていない、強い学習不足です。MobileNetV4-S（+5.9 / +3.7）よりはっきりしています。
5. 崩壊や不安定さはありません。best と last の PGD-10 の差は 0.05pt です。
6. **この run だけでは原因を分けられません。** LR、最適化手法（ConvNeXt は普通 AdamW で学習する。論点 B2）、warmup の長さ、50 epoch という予算、ランダム初期化そのもの、のどれが効いているかはわかりません。
   参考として、Anteater の事前学習カナリア（2080 Ti、決定論モード、lr 0.05、3 epoch）は epoch 2 で 48.65 / 26.67 でした。ただし初期化、LR、GPU、決定論モードがすべて違うので、比較ではなく背景情報です。

この結果は、論点 B1（「ConvNeXt-Atto と DeiT-Tiny は random-init で clean 約 30% と崩れている」）を、完走した run で確かめたものです。

## 費用の前提

## A：承認済みの Phase 1 事前学習セル（ConvNeXt-Atto・lr 0.015）を GPU0 で回す

- **GPU 時間**：約 25〜27 GPU-h（Hamster 4090 1 枚）。config 1 本と config テストの追加（事前学習・lr 0.015 以外はランダム初期化の config と同じ）と、新しい pinned worktree が必要です。Phase 1 の範囲（2026-09-26 承認）と plan 0104 のルールの中の作業で、新しい科学的契約ではありません。
- **確定すること**：同じレシピで、事前学習の初期化なら ConvNeXt-Atto がまともに学習できるか。つまり伸び悩みが「ランダム初期化から学ぶのが難しい」ことによるのか、「このレシピ（SGD・この LR）が ConvNeXt に合わない」ことによるのか。どちらかによって、B（レシピ探索）の中身が変わります。あわせて、ConvNeXt-Atto の「事前学習 − ランダム初期化」（論点 D1）の共通レシピでの値が出ます。
- **判定ルール（事前登録）**：比べる相手は MobileNetV4-S・事前学習・lr 0.015 の last PGD-10 31.92% と、今回の 16.53% です。
  - ConvNeXt-Atto 事前学習の last PGD-10 が **29.92% 以上**（MobileNetV4-S − 2pt）なら「伸び悩みは主にランダム初期化の問題。レシピは事前学習側では使える」。
  - **18.53% 以下**（今回 + 2pt）なら「初期化によらず、このレシピが ConvNeXt-Atto に合わない」。
  - その間なら「初期化とレシピの両方が絡む」。
  - clean は並べて報告しますが、判定には使いません。
- **リスク**：この run もまだ「MobileNetV4-S から移したレシピ」なので、A2 の原則（調整の手間を揃えて最良どうしで比べる）から見ると偏った条件のままです。結果は参考値の列に入り、最終的な比較には B のような調整が別に要ります。事前学習の重み（`d2_in1k`）の作られ方が MobileNetV4-S と違う点（論点 B4）も、そのまま残ります。

## B：ConvNeXt-Atto ランダム初期化のレシピ探索を新しい plan として始める

- **GPU 時間**：候補 3 本 × 25 epoch × 約 0.51 h ＝ 約 38〜42 GPU-h（Hamster GPU0 だけなら約 1.6 日。DeiT-Tiny が終われば GPU1 も使えます）。
  候補の例：SGD でピーク LR 0.1、AdamW（ConvNeXt の通常の設定に近い LR）で weight decay 1e-4、AdamW で warmup を長くしたもの。最適化手法と weight decay を変えるので、**新しい科学的契約で、新しい plan が要ります**。候補の中身は plan の中で人間が決めます。
- **確定すること**：LR／最適化手法を変えると、ConvNeXt-Atto の序盤の伸び（今回いちばん遅れていた部分）が変わるか。A2 の「調整の手間を揃える」を実際に回す最初の例にもなります。
- **判定ルール（事前登録）**：epoch 24（ピーク区間の最後）の val PGD-10 を、今回の同じ epoch の 12.17% と比べます。**14.17% 以上**（+2pt）の候補だけを 50 epoch に進めます。どれも届かなければ「試した範囲の LR／最適化手法は、序盤の伸びを変えない」とします。
- **リスク**：epoch 24 の順位が最終結果の順位と一致する保証はありません。MobileNetV4-S では、lr 0.025 の lr 0.05 に対するリードが epoch 24 の +2.78pt から最終の +0.66pt まで縮みました。代理指標を使うなら、A2 で決めたとおり順位相関の確認が要ります。AdamW＋weight decay 0.05 は MobileNetV4-S で崩壊したので（plan 0102）、その組み合わせを入れるなら崩壊の監視が要ります。また、ほかのモデル（DeiT-Tiny など）の結果を見ずに ConvNeXt-Atto だけ先に調整すると、「調整の手間を揃える」が崩れるおそれがあります。

## 推奨

**A** を推奨します。
A はすでに承認された Phase 1 の範囲とルールの中の作業で、新しい契約も新しい判断もいりません。空いた GPU をすぐ使えます。
しかも、B を設計する前に知りたいこと（伸び悩みが初期化のせいか、レシピのせいか）に直接答えます。事前学習でまともに学習できるなら、B はランダム初期化の最適化（warmup や LR）に絞れます。事前学習でも伸びないなら、B は最適化手法（AdamW）を中心にすべきです。
B は A2 の原則に沿う本命の作業ですが、ConvNeXt-Atto だけを先に調整すると、モデル間で調整の手間がそろわなくなります。DeiT-Tiny の結果と A の結果を見てから、全モデル共通の調整の枠組みとして plan にする方が公平です。
C は GPU を 1 日以上遊ばせるだけで、得るものがありません。

判断が変わるのは次の場合です。
- DeiT-Tiny も同じように伸び悩み、人間が「Phase 1 の共通レシピはやめて、すぐにモデルごとの調整に切り替える」と決めた場合。そのときは A の run は参考値にしかならないので、B を全モデル向けの plan として先に始める方がよいです。
- 事前学習側の Phase 1 の順番（どのモデルから回すか）について、人間に別の優先順位がある場合。そのときは A のモデルを入れ替えます。ConvNeXt-Atto を先にする理由は、上の原因の切り分けに役立つことだけです。
