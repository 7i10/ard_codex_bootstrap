条件は lr 5e-4 のセルと LR 以外すべて同じです。ImageNet-1k（元画像）、DeiT-Tiny、ランダム初期化、plain PGD-AT、教師なし、seed 0、224 px。

## ノイズの目安

- 検証の標準誤差は 1 run あたり PGD-10 で約 0.29pt、2 run の差では約 0.41pt です。
- ImageNet での seed 間の揺れはまだ測っていません。CIFAR 時代の経験では乱数だけで 1〜2pt 動きました。
- 今回の 2.02pt はその上端くらいです。「5e-4 の方が良い」という主張にはせず、採用 LR を決めるためだけに使います。
- B のしきい値 1.0pt は 0034 B と同じです。1pt 未満の差では 1 seed で読めないので、足しません。

## 費用の前提

- DeiT-Tiny の1セル: この run で 33.76 時間、5e-4 のセルで 33.00 時間（Hamster の 4090、隣の GPU も使用中）。lr を変えても速度は変わらないので、2e-3 も 33〜34 時間と見ます。Ferret で走らせても同じ 4090 なので同程度です。
- B が発火するのは 1e-3 の結果が出た後（約 34 時間後）なので、発火すると DeiT-Tiny の LR 確定はさらに約 34 時間遅れます（合計で今から約 2.8 日）。

## 選択肢

### A: 延長は 1e-3 の1回だけ（推奨）

- **GPU時間**: 追加 0。
- **分かること**: 4点の中での DeiT-Tiny の採用 LR。
- **事前に決めたルール**（0034 B のまま）: 4点そろった時点で、最後の epoch の内部検証 PGD-10 が最大の LR を採用する。1e-3 が勝っても足さない。判定は PGD-10 だけ。
  加えて、1e-3 が 5e-4 より 1.0pt 以上高かった場合は、論文と best-vs-best の表に「DeiT-Tiny の最適 LR はグリッドの上にあるかもしれない」と書く。
- **リスク**: 1e-3 が大きく勝つと、DeiT-Tiny だけ実力より低い数字で比べることになるかもしれません。

### B: 1e-3 も勝ったら 2e-3 を1セル足す

- **GPU時間**: 追加 0〜約 34 時間（DeiT-Tiny のみ、発火したときだけ）。
- **分かること**: 上り坂がどこで止まるか。
- **事前に決めるルール**（1e-3 の結果を見る前に、この packet で記録）:
  - 4点そろった時点で、1e-3 が argmax、かつ 1e-3 − 5e-4 ≥ 1.0pt（最後の epoch の内部検証 PGD-10）なら、lr 2e-3 を1セル足す（ほかは 5e-4 のセルと同じ、seed 0）。
  - 5点の argmax を採用する。2e-3 が勝っても、それ以上は足さない。
  - 1e-3 が argmax でも差が 1.0pt 未満なら足さず、1e-3 を採用する。
- **リスク**: DeiT-Tiny だけ予算が2セル多くなり、「同じ予算で best-vs-best」がさらに崩れます。
  2e-3 は DeiT の公式レシピを線形に直した値（1.25e-4）の 16 倍で、不安定になるかもしれません。その場合もそのまま比較に入れます。
  ConvNeXt-Atto には適用しません（その 1e-3 の結果を見てから別に決めることになり、事前登録ではなくなります）。

## 推奨

A を推奨します。0034 B は「延長は1回だけ」と決めてから 1e-3 を足しました。その結果を見る前にルールを広げると、
モデルごとに延長回数が変わり、Phase 1 の「同じ手順で LR を選ぶ」という前提が崩れます。LR を2倍にしたときの伸びは
+4.1pt → +2.0pt と半分になっているので、1e-3 で止まる見込みもあります。1e-3 が大きく勝った場合は、A でもその事実を
論文に書くので、隠れることはありません。次のどれかなら B に変えます。(1) DeiT-Tiny が Phase 1 の結論（ViT 系の
順位）を左右するモデルで、低めの数字で比べるのを避けたいとき。(2) Phase 1 の締め切りまでに約 34 時間の余裕が
あるとき。(3) ConvNeXt-Atto の 1e-3 の結果を見る前に、同じルールを ConvNeXt-Atto にも事前登録したいとき（その場合は
B を両モデルに広げた別の選択肢として書き直します）。
