# 0050: SiLU＋weight decay の除外、MobileNetV4-S seed 0 が完了（PGD-10 は +0.39pt で効果なし）

## 結果のまとめ

記録: `docs/plans/0103-lightweight-imagenet-architecture-survey.md` の Progress log、2026-10-13 (postrun, Phase 2 SiLU with no weight decay on norm/bias)。
証拠台帳 `docs/RESEARCH_STATUS_SUMMARY.md` の最後の行。結果のコミットは `21acc83`。
この契約には集計スクリプトが無いので、`docs/experiments/` の record はありません（数字は run-bundle の manifest と `epoch-metrics.jsonl` から読みました）。

この run は SiLU の run（`plan0103-phase2-mnv4s-silu-s0-v1`、55.45 / 33.27）と同じ学習で、違いは1つだけです。
BatchNorm の scale と shift、バイアス（1次元以下のパラメータ）に weight decay をかけません。畳み込みと全結合の重みには今までどおり 1e-4 をかけます。
比べる相手の SiLU の run は、source（`5dd329e`）も実行のしかた（決定的・eager）も同じです。なので、decision 0042 の「source の違い」の問題はこの比較には入りません。
違うのは実行したマシン（Ferret と Hamster）と、途中で1回再開したことだけです。

条件: ImageNet-1k（元画像）、MobileNetV4-S（ReLU をすべて SiLU に置き換え）、ランダム初期化、plain PGD-AT、教師なし、seed 0、224 px。
学習時の攻撃は PGD-3（l_inf 4/255、step 8/765、ランダムスタート）、評価は PGD-10（同じ eps と step）。
SGD（Nesterov、momentum 0.9）、ピーク LR 0.025、multistep（10 epoch のウォームアップ、epoch 25 と 38 で 1/10）、50 epoch、world size 1、バッチ 128。
数字はすべて内部検証（学習データから取り分けた 25,620 枚）で、公式テストではありません。AutoAttack も公式評価もまだです。

- **事前ルールの判定は「SiLU では効果なし」です。** decision 0043 の B で run の前に決めたルールは、Δ = (SiLU＋除外) − (SiLU＋全部にかける) を、最後の普通の重み・取り分けた画像すべての PGD-10 で見るものでした。
  Δ = +0.39pt（25,620 枚のうち 100 枚）で、|Δ| < 0.5 なので「SiLU では効果なし。ReLU で下がったので、除外は採用しない」に当たります。+0.5 に届くには、あと 29 枚正解が必要でした。
  2本の差の誤差（SE）は PGD-10 で約 0.37pt なので、+0.39 は誤差1つ分です。
- **clean は +1.05pt 上がりました**（SE の約 2.4 倍）。残りの 20,620 枚でも +1.12、EMA の重み同士でも +1.01 で、向きはそろっています。ただし事前ルールは PGD-10 で決めていて、clean はルールの外です。
- **学習データへの当てはまりは良くなりました。** 学習損失は 3.502（SiLU は 3.608）、学習バッチの頑健精度は 30.75%（29.53%）、学習画像（probe）は clean +1.80 / PGD-10 +0.75 です。
  増えた当てはまりは、見ていない画像の clean には出ていますが、PGD-10 にはほとんど出ていません。ReLU では除外しても当てはまりは変わらず、見ていない画像の PGD-10 が下がりました。
- **サブセット（5,000 枚）と全体（25,620 枚）で PGD-10 の差の向きが逆です。** 最後の epoch でサブセットは −0.34、全体は +0.39 です。どちらも誤差の内側なので、「差がない」という読みと合っています。
- **2×2 としての読み**: 除外の効果は ReLU で −1.14（source が違う）、SiLU で +0.39 です。差の +1.53pt が交互作用の見積もりですが、seed 1本ずつの4本から出した数で、ReLU 側は source の違いも混ざっています。
- **副産物: EMA のウォームアップ中の遅れは、除外で消えると言えるようになりました。** epoch 9 で EMA の重みはサブセットで 28.78 / 17.60 です。同じ source・同じ実行のしかたで全部にかけた SiLU の run では 7.60 / 4.06 でした。
  decision 0043 では「weight decay の変更か source の違いか」が未確認でしたが、この組は source も実行のしかたも同じなので、weight decay の変更の方です（1組だけで、仕組みは確かめていません）。最後の EMA と普通の重みの差は +0.24pt で、終わりの数字には効いていません。
- 学習崩壊の見張りは一度も発動していません。best と last の差は 0.02pt です。Ferret の再起動で epoch 27 の後に1回止まり、同じ source の `last.pt` から再開しました（ドライバは 595.84 → 595.99）。再開の前後で数字に段差はありませんが、この run についてビット単位の連続性は確かめていません。

## 選択肢

### A: 記録だけで閉じる

- **GPU時間**: 追加 0。
- **わかること**: 新しいことはありません。2×2 の4マスがそろい、0043 B の事前ルールで「除外は採用しない」が確定します。
- **事前ルール**: 0043 B のルール（|Δ| < 0.5 → 採用しない）をそのまま当てます。標準は weight decay を全パラメータにかけるまま。SiLU を標準にするかは 0044 で別に決めます。
- **リスク**: clean の +1.05 が本物なら、clean を少し上げる無料の変更を見送ることになります。ただし、この研究の主な指標は PGD-10 で、そこには差がありません。

### B: SiLU＋除外と SiLU の seed 1 を回す

- **GPU時間**: 2本で約 38〜41 時間（Hamster の 4090 1枚ずつ、並べれば実時間は約 20 時間）。根拠は Hamster での SiLU の run の実測 928〜943 枚/秒（1 epoch 約 1,340〜1,370 秒の学習＋約 50 秒の評価など、× 50）です。Ferret の今回の速さ（356〜491 枚/秒）では2倍以上かかります。0044 の C で SiLU の seed 1 を回すなら、追加はこの1本だけで約 19〜20.5 時間です。
- **やり方**: `imagenet_mobilenetv4_pgd_at_phase2_silu_wdexcl.yaml` と SiLU の設定を、`5dd329e` の worktree から seed 1 で回します。2本は同じホストで回します。
- **わかること**: clean の差が seed を変えても出るか。seed 0 と seed 1 の2組で向きがそろえば、「この2つの seed では除外は clean を上げ、PGD-10 は変えない」という向きの結論になります（母集団の主張にはしません）。
- **事前ルール（run の前に固定します）**: seed 1 の Δclean と ΔPGD-10（SiLU＋除外 − SiLU、最後の普通の重み、取り分けた画像すべて）を見ます。
  - Δclean ≥ +0.5 かつ ΔPGD-10 ≥ −0.5 → 2組とも clean が上がり PGD-10 は下がらない。SiLU の標準に除外を入れるかを別の packet で決める。
  - それ以外 → 除外は採用しない（A と同じ結論）。
- **リスク**: clean は 0043 の事前ルールの指標ではないので、後から選んだ指標を確かめに行く形になります。そのため、結果がそろっても「向きの結論」以上にはなりません。clean の差が 0.5〜1pt 程度だと、seed 2組では揺れと区別しにくいです。PGD-10 で効果のない変更に約 20〜40 GPU時間を使います。

## おすすめ: A

0043 の B で run の前に決めたルールが、そのまま「採用しない」を指しています。PGD-10 の差（+0.39）はどの noise floor よりも小さく、ここから PGD-10 について言えることはありません。
clean の +1.05 は気になる数字ですが、事前に決めた指標ではなく、追いかけるには少なくとも seed 1 の1〜2本が必要です。
この研究の主な問いは頑健さ（PGD-10）なので、そこに効かない変更に GPU を使うより、ほかの Phase 2 の候補に回す方が良いと考えます。
副産物の「除外で EMA のウォームアップ中の遅れが消える」は、終わりの数字に効いていないので、記録に残すだけで十分です。

**判断が変わる場合**:
- 0044 で C（SiLU の seed 1）を選ぶなら、B の追加は1本（約 19〜20.5 GPU時間）に減り、同じ seed の比較が手に入ります。そのときは B も十分に考えられます。
- clean の精度を、頑健さと並ぶ目標として重視するなら B にします。
- 0044 で D（SiLU を標準にしない）を選ぶなら、SiLU の上の除外を調べる意味はなくなるので A です。

`chosen` は人間が記入します。記入されるまで、この packet に関わる新しい学習は始めません。

## 決定（2026-10-13、本人、チャットで回答）

**A を選択（ただし結論は「保留」）。** 除外は採用せず、MobileNetV4-S の標準は SiLU だけ（weight decay は全パラメータ）。ただし「効果なし」とは言い切らない：ReLU では −1.14、SiLU では +0.39 で、活性化関数によって向きが変わる可能性は seed 1本ずつでは否定できない。seed は今は足さず、最終的なレシピを固める段階でほかの要素とまとめて確かめる。詳細は discussion register B（2026-10-13）。
