# 0048: Phase 2 の AWP、MobileNetV4-S seed 0 が完了（clean −25.38、PGD-10 −13.26）

## 結果のまとめ

記録: `docs/plans/0103-lightweight-imagenet-architecture-survey.md` の Progress log、2026-10-13 (postrun, Phase 2 AWP)。
証拠台帳 `docs/RESEARCH_STATUS_SUMMARY.md` の最後の行。結果のコミットは `a6fdaca`。
この契約には集計スクリプトが無いので、`docs/experiments/` の record はありません（数字は `epoch-metrics.jsonl` と run-bundle の manifest から読みました）。

AWP（Adversarial Weight Perturbation）は、入力だけでなく重みにも「損失が増える方向のずれ」を加えて学習する方法です。
各 step で、まず普通の PGD-3 で攻撃画像を作ります。
次に、その画像で損失が増える向きを1 step だけ調べ、各層の重みを「その層の重みの大きさの 1%（γ=0.01）」だけその向きにずらします（BN のパラメータは動かしません）。
ずらした重みで学習の順伝播・逆伝播・更新を行い、更新の後でずれを戻します。
実装は公式コード（csdongxian/AWP、`a7acf5d8`）の書き写しで、公式コードとの一致テストも通っています。
それ以外は基準＋EMA と同じレシピです（50 epoch、224 px、SGD lr 0.025、LR は epoch 25 と 38 で下げる、weight decay 1e-4 を全パラメータに、標準の拡張、Phase 2 のテンプレート）。

条件: ImageNet-1k（元画像）、MobileNetV4-S（ReLU）、ランダム初期化、教師なし、seed 0、world size 1、バッチ 128、決定的モード、CUDA Graphs。
数字はすべて内部検証（学習データから取り分けた 25,620 枚）で、公式テストではありません。AutoAttack も公式評価もまだです。

- **基準と比べると clean −25.38、PGD-10 −13.26。** 2本の差の誤差（SE）は clean 約 0.43pt、PGD-10 約 0.37pt なので、約 59 SE と 36 SE です。数字の水準は、Phase 1 の ConvNeXt-Atto（30.68 / 16.53）とほぼ同じです。
- **Phase 2 のルール**（1.5pt 以上で「効果あり」、0.5〜1.5pt で「保留」、0.5pt 未満で「効果なし」）では、大きさは「効果あり」の段で、向きは損です。
- **最初の epoch から学習が遅い。** warmup の終わり（epoch 9）でサブセットは 7.80 / 5.08、基準は 30.96 / 15.98。LR が高い間に差は少し縮みますが（epoch 24 で −15.48 / −6.68）、**LR を下げてもほとんど伸びません。** epoch 24→25 の伸びは PGD-10 で +0.98（基準 +5.18）、epoch 37→38 は −0.02（基準 +0.50）。epoch 25 以降、サブセットの PGD-10 は 16.06〜17.00 で横ばいです。
- **汎化の問題ではなく、学習画像にも当てはまっていません。** 学習画像 2,000 枚（拡張なし）で 27.55 / 17.25、基準は 59.80 / 34.40。学習画像と取り分けた画像の差は −0.92 / −0.20 で、ほぼゼロです（基準は +5.95 / +3.69）。学習の損失は最後に 5.640（基準 3.697、1000 クラスを当てずっぽうに選ぶと 6.91）で、後半 25 epoch で 5.682 から 5.640 にしか下がっていません。
- **AWP が直そうとする問題が、この設定にはありません。** AWP は「頑健性の過学習」（途中で頑健性が最高になり、その後下がる）への対策として提案されました。私たちの ImageNet の run では、best と最後の差は 29 本の中央値で 0.1pt で、今回も +0.05pt です。この設定ではモデルはむしろ学習しきれておらず、重みを 1% ずらす負荷がその足りない学習力をさらに削った、と読めます。原因として確かめたわけではありません。
- 崩壊の見張りは一度も作動していません（サブセットの最大の落ち込みは 0.36pt）。
- 時間: 開始から終了まで 21.53 時間（再起動による中断を含む）。学習だけで約 19.6 時間、822〜958 枚/秒（Ferret、CUDA Graphs）。

**注意点**: seed は1つだけ。読んだのは γ=0.01・warmup 0 の1点だけです（AWP の論文は CIFAR-10 の ResNet-18 / WRN で γ を調整しています）。
source（`5dd329e` と `d836c03`、0042 B として確認は保留中）とホスト（Ferret と Hamster）が基準と違い、途中で NVIDIA のドライバが 595.84 から 595.99 に変わっています（CUDA Graphs と eager のビット一致テストは新しいドライバで通過、plan 0106）。
同じ `5dd329e` から回したほかの run の基準との差は −4.65〜+2.56pt で、13.26pt の損はこれらの要因で説明できる大きさを大きく超えています。

## 揺れの大きさ（ノイズの床）

MobileNetV4-S の seed 0 と seed 1 の差は 0.36pt、full val で2本を比べた差の SE は PGD-10 で約 0.37pt です（plan 0103、2026-10-11 の記録）。
今回の −13.26pt はこの床の 35 倍以上あり、seed 1 を回しても向きは変わらないと見込めます。
そのため seed 1 は選択肢に入れていません。
B は、基準を 1.5pt 以上（Phase 2 の「効果あり」）上回るかどうかで判定するので、床より十分大きい差だけを読みます。

## 選択肢

### A: ここで閉じる

- **GPU 時間**: 0。
- **分かること**: 「MobileNetV4-S では、AWP γ=0.01 は学習不足を起こし、PGD-AT の基準より clean で 25.38pt、CE PGD-10 で 13.26pt 低い」と記録して AWP の線を閉じます。AWP の他の run はキューに入れません。空いた GPU は残りの Phase 2 の候補（蒸留など）に回せます。
- **事前に決めた判定**: なし（判定をしない選択肢です）。
- **リスク**: γ を小さくすれば損が消えるかどうかは分からないままです。ただし、γ を小さくするほど AWP は普通の PGD-AT に近づくので、「基準を 1.5pt 上回る」余地はもともと小さいと見ています。

### B: γ=0.001 の AWP を1本だけ回す

- **GPU 時間**: 約 20〜23 時間（今回の学習時間 19.6 時間と、Ferret の再開前の 897〜958 枚/秒を基準に。γ を変えても計算量は同じ）。4090 1枚。
- **分かること**: 重みのずれを 1/10 にすると、学習不足が解けて基準を上回るかどうか。
- **事前に決めた判定**: 最後の普通の重みで full val PGD-10 が **32.21 以上**（基準 30.71 + 1.5）なら AWP の線を続ける。30.71〜32.21 なら「基準と同等で、clean を見て判断」として人間に返す。30.71 未満なら閉じる。
- **リスク**: 頑健性の過学習が無い設定で、AWP が基準を 1.5pt 上回る理由が見当たりません。γ はメソッドの係数で、ε・step 数・評価の攻撃は変えません（新しい config 1つで済み、新しい科学契約ではありません）。γ=0.001 が「小さすぎて何も変わらない」と「まだ大きすぎる」のどちらに落ちても、1本では γ の良い値は決まりません。

## おすすめ: A

−13.26pt はノイズの床の 35 倍以上で、Phase 2 のルールでもはっきりした損です。
しかも原因の読み（学習不足の設定に、過学習対策を足した）は γ の値によらず当てはまるので、γ を下げても得をする見込みは低く、B は1日分の GPU に見合いません。
Phase 2 の目的（同じ計算量で基準を超える工夫を探す）から見ても、AWP は1 step あたりの計算が増えるうえに精度が大きく下がっています。

**判断が変わる条件**: Ferret で走っている標準の拡張・100 epoch の run（`standard-100ep`）で、best と最後の差が 1pt 以上になる（頑健性の過学習が出る）場合は、その長い学習に限って AWP を試す意味が出ます。
そのときは新しい決定パケットで、100 epoch の AWP を提案します。
また、0042 B（source の確認）で `5dd329e` 自体に問題が見つかった場合は、この判断を見直します。

## 決定（2026-10-13、本人、チャットで回答）

**A を選択。** AWP は有効ではないと結論づける。設定（γ=0.01、ウォームアップなし）は公式コード AT-AWP の既定値で、AWP をそのまま試したものとして妥当。基準には AWP が直す頑健性の過学習がなく（検証の PGD-10 は最後まで上がり、学習画像の抜き出しとの差は 4.4pt）、AWP は学習への当てはまりを下げて差を縮めただけ（学習損失 3.70 → 5.64）。γ を弱めても基準に近づくだけなので B は回さない。今後は学習不足を補う手法で組み立てる。詳細は discussion register B（2026-10-13）。
