## 選択肢

### A: 記録だけで閉じる

- **GPU時間**: 追加 0。
- **わかること**: 新しいことはありません。この run の3つの目的（設定チェック、EMA の効果、基準）はすべて答えが出ています。
- **事前ルール**: 適用済みです（差 0.00pt → 「設定の影響なし」。EMA +0.10pt → 0.5pt 未満で「効果なし」）。
  53.85 / 30.71 を MobileNetV4-S の Phase 2 の基準とします。EMA は共通設定に残します（他モデルの基準＋EMA で EMA の効果を測る、10/10 の決定のとおり）。
- **リスク**: `5dd329e` の run（SiLU、IDBH、TRADES、SE）を、同じ source の基準なしで 53.85 / 30.71 と比べることになります。
  もし `5dd329e` が普通の full AT を少しでも違う数字に学習するなら、その差が候補の効果に混ざります。ビット単位の一致が崩れていても、大きさが 0.5pt 未満なら判定には効きませんが、それも確かめていないことになります。

### B: `5dd329e` で 2 epoch だけ回して、ビット単位の一致を確かめる

- **GPU時間**: 約 0.6〜1.0 時間（4090 1枚）。根拠はこの run の 1 epoch あたり約 1,066 秒の学習と約 51 秒の評価などです。2 epoch で約 37 分、起動と後片付けを足して幅を持たせました。
- **やり方**: `5dd329e` の worktree（`source-5dd329eaf31f`、すでにあります）から、この run の設定ファイル `imagenet_mobilenetv4_pgd_at_phase2_baseline_ema_cg.yaml` を**そのまま**（50 epoch のまま）起動し、epoch 1 の行が書かれたら止めます。
  epoch 数を 2 に変えると学習率の予定が変わるので、変えません。止めた run は結果としては使いません。
  置き場所は Hamster のどちらかの GPU が次に空いたとき、または Ferret（短い仕事なので Ferret の使い方の約束に合います）。
- **わかること**: `5dd329e` が、この学習の経路を `d836c03`・`65369a3` と同じに学習するか。
- **事前ルール（ここで決めて、run の前に固定します）**:
  - epoch 0 と 1 の学習損失・学習バッチの頑健精度・probe の clean と PGD-10・サブセットの clean と PGD-10（普通の重みと EMA）が、この run と最後の桁まで同じ → `5dd329e` の MobileNetV4-S Phase 2 の run は、53.85 / 30.71 とそのまま比べてよい。
  - どれか1つでも違う → `5dd329e` の run と 53.85 / 30.71 の比較には注意書きをつける。`5dd329e` で 50 epoch の基準を回し直すか（約 15.5 GPU時間）は、別の decision packet で人間が決める。
- **リスク**: 2 epoch の一致は、残り 48 epoch の一致を保証しません。ただし決定的モードでは、最初の数百ステップが同じなら、その後だけ違う経路に入る理由は、epoch 25 と 38 の学習率の切り替えや最後の評価の処理くらいです。
  この確認のために、いま走っている Phase 2 の run を止めることはしません。

### 選択肢にしなかったもの

- **EMA を共通設定から外す**: 遅くなるのは 1.5〜2.7% で、EMA が原因かホストが原因かも分けていません。CUDA Graphs の拡張で使った「5% 以上速くなるならやる」という目安に届きません。また、10/10 に人間が「基準＋EMA は全モデルで1本ずつ」と決めていて、EMA の効果は他モデルでも測る予定です。
- **判定を EMA の重みで読む**: 事前ルールを後から変えることになります。
