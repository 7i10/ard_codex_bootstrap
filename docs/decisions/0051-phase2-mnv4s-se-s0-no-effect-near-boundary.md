# 0051: SE（パラメータ数をそろえた版）、MobileNetV4-S seed 0 が完了（PGD-10 は +0.41pt で効果なし、境界の近く）

記録: `docs/plans/0103-lightweight-imagenet-architecture-survey.md` の Progress log、2026-10-13 (postrun, Phase 2 SE)。

この run は基準＋EMA（`plan0103-phase2-mnv4s-baseline-ema-s0-v1`、53.85 / 30.71）と同じ学習で、モデルだけが違います。
- 全 UIB ブロックに SE を入れました（EfficientNet-B0 と同じ作り。絞りの幅はブロック入力の 0.25 倍、sigmoid のゲート）。活性化関数は ReLU のままです。

- つまり「SE を足す」と「head を細くする」の2つを同時に変えています。SE だけの効果（head はそのまま、パラメータ +6.61%）は、別に用意した fullhead の対照で見る設計でした（まだ回していません）。

## 選択肢

### A: 記録だけで閉じる

- **GPU時間**: 追加 0。
- **わかること**: 新しいことはありません。Phase 2 のルールどおり、パラメータ数をそろえた ReLU の SE は「効果なし」で確定します。fullhead の対照も事前の条件どおり回しません。
- **事前ルール**: Phase 2 のルール（< 0.5pt → 効果なし）と fullhead の条件（0.5〜1.5pt のときだけ）をそのまま当てます。SE を続けるかは、SiLU＋SE と SiLU（33.27）の比較を同じ Phase 2 のルールで読んで決めます。
- **リスク**: 本当の効果が 0.5pt 前後なら、それを見落とします。ただ、その大きさは seed の差と同じで、seed 1〜2本では確かめきれません。また 0042 の B（source の一致確認）が「`5dd329e` は基準より 0.1pt 以上低く学習する」と出た場合は、この判定を読み直す必要があります（その場合も「保留」に移るだけです）。

### B: SE（ReLU）の seed 1 を回す

- **GPU時間**: 約 20〜21 時間（Hamster の 4090 1枚）。根拠は今回の実測 20.47 時間（873〜888 枚/秒、eager）です。Ferret だと混み具合で2倍以上かかることがあります（silu-wdexcl の実績 43 時間）。
- **やり方**: `imagenet_mobilenetv4_se_pgd_at_phase2_random_lr0025.yaml` を `5dd329e` の worktree から seed 1 で回します。比べる相手は既にある MobileNetV4-S seed 1 の基準 run（Phase 1、plan 0103 の 2026-10-11 の記録。テンプレートは学習に影響しないことを確認済み）です。
- **わかること**: seed 0 の +0.41 が seed 1 でも 0.5pt 未満か。2組で向きがそろえば「この2つの seed では、パラメータ数をそろえた SE は PGD-10 を 0.5pt 以上は動かさない（または動かす）」という向きの結論になります（母集団の主張にはしません）。
- **事前ルール（run の前に固定します）**: seed 1 の Δ（SE − 基準 seed 1、最後の普通の重み、取り分けた画像すべての PGD-10）を見ます。
  - Δ ≥ +0.5 → seed 0 と合わせて「保留」とし、fullhead の対照（約 20 時間）を回すかを別の packet で決める。
  - Δ < +0.5 → 「効果なし」で閉じる（A と同じ結論）。
- **リスク**: 比べる相手の seed 1 の基準は Phase 1 の run で、source と実行のしかたがまた違います。境界の近さが問題の選択肢なのに、同じ種類の不確かさが残ります。期待される差（0.4〜0.6pt）は seed の差と同じ大きさなので、2組でも判定ははっきりしない見込みが高いです。約 20 GPU時間を、どちらに転んでもほぼ変わらない判断に使うことになります。

## おすすめ: A

事前ルールは「効果なし」を指しており、fullhead の対照も事前の条件では回しません。+0.41pt は seed の差（0.36pt）と同じ大きさで、seed をもう1本足しても判定がはっきりする見込みは低いです。
学習データへの当てはまりも動いておらず、register B の「学習不足を補う」方向の手がかりにもなっていません。SE をこの先使うかは、すでに進んでいる SiLU＋SE の run（SiLU 33.27 との比較）で決める方が、今の標準（SiLU）に直接つながります。

**判断が変わる場合**:
- 0042 の B（source の一致確認）を回して、`5dd329e` が基準より 0.1pt 以上低く学習すると出たら、この判定は「保留」に移ります。そのときは B（seed 1）を考えます。
- SiLU＋SE が SiLU より 0.5pt 以上上がったら、SE が SiLU の上でだけ効く可能性が出ます。そのときは ReLU の SE を蒸し返すより、SiLU＋SE の seed 1 を考える方が筋です。
- SE を EfficientNet-B0 との比較の材料として重視する（「MobileNetV4 に B0 の部品を足すと近づくか」を論文の問いにする）なら、B と fullhead の対照に価値が出ます。

`chosen` は人間が記入します。記入されるまで、この packet に関わる新しい学習は始めません。

## 決定（2026-10-15、本人、チャットで回答）

**A を選択（ただし結論の書き方を変える）。** 「効果なし」とは断定しない。パラメータ数をそろえた SE の効果は、ReLU で +0.41、SiLU で +0.56（SiLU＋SE 56.42 / 33.83）と、独立な2つの比較で同じ向きの小さな正の値。結論は「パラメータ数をそろえると SE の効果は小さい（+0.5 前後、1pt 未満）」。白黒をつけるための seed は「今は」足さない。理由：スマートフォンでの計算が遅くなる代償を払っても、大きな効果は得られないと考えるため。MobileNetV4 の論文（arXiv:2404.10518、6章）も、SE は DSP での対応が弱くアクセラレータで遅いことを理由に、標準的な部品だけで構成している。
