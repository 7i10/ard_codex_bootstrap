# 0062: 勾配だけ滑らかにする（攻撃と更新の両方）、MobileNetV4-S seed 0 が完了（基準＋EMA より clean +2.06 / PGD-10 −7.19）

## 結果のまとめ

記録: `docs/plans/0107-train-time-capacity-deploy-plain.md` の Progress、2026-10-18 (postrun, smooth backward attack and optimizer)。
証拠台帳 `docs/RESEARCH_STATUS_SUMMARY.md` の最後の行。結果のコミットは `dd58479`（`Record plan0107-mnv4s-smoothgrad-both-s0-v1 results`）。
この契約には集計スクリプトが無いので、`docs/experiments/` の record はありません（数字は run-bundle の manifest と `epoch-metrics.jsonl` から読みました）。

この run は MobileNetV4-S の基準＋EMA と同じ設定で、違いは1つだけです。
ReLU の逆伝播で、ReLU の微分の代わりに softplus（beta 10）の微分を使います。
使う場所は、学習時の攻撃（PGD-3）と重みの更新の両方です。
順伝播は ReLU のままなので、デプロイするモデルは普通の ReLU モデルです。
選抜・検証・評価の攻撃（PGD-10）は、本当の ReLU の勾配を使います。
もとにした研究は Smooth Adversarial Training（Xie et al. 2020）で、ResNet-50・PGD-1 では、この「両方」の使い方で頑健精度が 33.0 → 36.9 に上がっていました。

条件: ImageNet-1k（元画像）、MobileNetV4-Conv-S、ランダム初期化、plain PGD-AT、教師なし、seed 0、224 px。
学習時の攻撃は PGD-3（l_inf 4/255、step 8/765、ランダムスタート）、評価は PGD-10（同じ eps と step）。
SGD（Nesterov、weight decay 1e-4）、ピーク LR 0.025、multistep（10 epoch のウォームアップ、epoch 25 と 38 で 1/10）、50 epoch、world size 1、バッチ 128。
数字はすべて内部検証（学習データから取り分けた 25,620 枚）で、公式テストではありません。AutoAttack も公式評価もまだです。

- **clean は +2.06pt 上がっています。**

## 選択肢

### A: attack_and_optimizer の範囲を閉じる（おすすめ）

- **GPU時間**: 0。
- **わかること**: 新しいことはわかりません。この範囲に GPU をこれ以上使わないことを決めます。
- **事前ルール**: この packet で A が選ばれたら、plan 0107 の方法候補 1 の `attack_and_optimizer` を「MobileNetV4-S、beta 10、PGD-3 では下がる（seed 1本、−7.19pt）」として閉じ、追加の run は出しません。
  plan 0107 の次（optimizer だけの続き、hard-swish、構造の再パラメータ化、SiLU か ReLU か）は、残り2本の packet で決めます。
- **リスク**: 下がった理由は確かめないままです。論文で「SAT の両方の使い方は小さいモデルでは逆効果」と書くには、理由の説明が弱くなります。

### B: 保存済みのチェックポイントで攻撃の強さを比べる診断を足す

- **GPU時間**: 約 0.5〜2 時間（2つのチェックポイント × サブセット 5,000 枚 × 2種類の PGD-3。1 epoch の検証にかかる時間からの見積もり）。ほかに、診断用のコードを書いてレビューする手間がかかります。
  今の評価の仕組みは「評価の攻撃は必ず本当の勾配」という決まりなので、滑らかな勾配の攻撃は評価用の CLI からは使えません。学習には関わらない、別の診断スクリプトとして作ります（新しい診断の契約になります）。
- **やり方**: この run の `last.pt` と基準＋EMA の `last.pt` に、同じ 5,000 枚・同じ乱数で、(1) 本当の勾配の PGD-3、(2) 滑らかな勾配（beta 10）の PGD-3 をかけ、eval モードの頑健精度を比べます。eps・step・ランダムスタートは学習時と同じです。
- **わかること**: 滑らかな勾配の攻撃が、本当のネットワークに対してどれだけ弱いか。それが今回の −7.19pt の説明になるか。
- **事前ルール**: g = (滑らかな勾配の PGD-3 の頑健精度) − (本当の勾配の PGD-3 の頑健精度)、この run の `last.pt` で測ります。
  g ≥ 2pt → 「学習時の攻撃が弱くなったことで説明できる」と記録します。
  g < 0.5pt → 「攻撃の弱さでは説明できない」と記録し、理由は未解明として残します。
  0.5 ≤ g < 2pt → 「一部は説明できる」と記録します。
  基準の `last.pt` でも同じ g を出し、並べて記録します。どの結果でも、この範囲を閉じる判断（A）は変えません。
- **リスク**: コードとレビューの手間が、GPU 時間より大きくなります。結果は説明を強めるだけで、次の実験の選び方はほとんど変わりません。

### C: beta 50 で attack_and_optimizer をもう1本回す

- **GPU時間**: Ferret で約 38〜41 時間（今回 40.4 時間、optimizer だけの run が 37.7 時間）。Hamster なら約 16〜22 時間の見込み（基準＋EMA が CUDA Graphs で 15.5 時間、SiLU が eager で 19.3 時間）。
  beta は config の値を変えるだけですが、新しい config と、plan 0107 への追記（新しい腕として）が要ります。
- **わかること**: ReLU に近い滑らかさ（beta 50）なら、攻撃が弱くなる影響を抑えつつ、SAT の効果が出るか。
- **事前ルール**: Δ = この新しい run − 基準＋EMA（最後の普通の重み、取り分けた画像すべての PGD-10）。
  Δ ≥ +0.5pt → 続ける（seed 1 か、optimizer だけの範囲でも beta 50 を試すかを、改めて packet で決める）。
  Δ < +0.5pt → attack_and_optimizer を閉じる。
- **リスク**: beta 10 では −7.19pt、optimizer だけでも −1.21pt で、どちらも下がる向きです。beta を上げると本当の ReLU に近づくので、良くても「基準と同じ」に近づくだけの可能性が高いです。plan 0107 の構造の再パラメータ化や蒸留の検証と GPU を取り合います。

seed 1 は選択肢に入れていません。差が SE の約 18 倍、seed の差の約 20 倍で、seed 1 で向きが変わる見込みは低く、結論は動かないためです。

## おすすめ: A

−7.19pt は、ばらつきの目安を大きく超えた、はっきり下がる結果です。optimizer だけの run も下がる向きで、滑らかな勾配の案は MobileNetV4-S では2つの範囲とも上がっていません。
plan 0107 の採用条件（SiLU 並みの上がり幅）には遠く届かないので、GPU は hard-swish の結果を見たうえでの次の案（構造の再パラメータ化、蒸留の検証）に残すのがよいと考えます。

## 決定（2026-10-18、本人、チャットで回答）

**A を選択。「勾配だけ滑らかにする」は、更新だけ・攻撃と更新の両方とも閉じる。** 人間の求めで、なぜ効かなかったかを保存済みのチェックポイントで調べた（CPU、学習なし、正式な結果ではない。選択肢 B の問いに、事前登録とは違う手順で答えたもの）。

- **原因の根：MobileNetV4 の ReLU の入力はとても小さい。** 最終の基準モデルでは ReLU の入力の80%が |x|<0.3 にある（敵対的訓練した ResNet-18 では49%、入力の標準偏差は 0.1〜0.2 に対し ResNet-18 は 0.7〜1.8）。そのため SAT の β=10 は、このモデルでは ReLU のよい近似にならない（ResNet でいえば β≈1.5〜2 に相当）。
- **攻撃と更新の両方（−7.19）：学習中の攻撃が弱かった。** 最終モデルで、滑らかな勾配の PGD-3 は本当の勾配の PGD-3 より 8.2pt 弱い（1000枚、正答率 38.1 対 29.9）。滑らかな勾配でだけ破れる画像は0枚。β を 50 にすると差が消える（29.7）。つまり実質的に「弱い攻撃での敵対的訓練」になり、clean は上がって本当の頑健性が下がった。学習画像での本当の勾配の PGD は、学習が進むほど基準から離れた（12エポックで −0.3、49エポックで −7.0）。
- **更新だけ（−1.22）：方向はほぼ正しいが、前半の層の更新が縮んだだけ。** 滑らかな勾配と本当の勾配の、ノイズを除いた方向の一致（cos）は 0.94〜0.97 で ResNet-18 と同程度。ただし stem から stage 1 では、更新の大きさが本当の勾配の 0.55〜0.67 倍に縮む（隠れた学習率の引き下げ）。学習損失は一度も基準より下がらず、SAT の仕組み（学習損失が下がる）は起きなかった。
- **SiLU / hard-swish が効くのは、順方向の関数が滑らかになるから。** 損失の局所的な線形性（ε 球の中での入力勾配のそろい方）は SiLU・hard-swish が 0.995、ReLU が 0.977。線形近似の誤差も約25%小さい。逆方向だけ変えても、デプロイされる ReLU の関数は変わらないので、この効果は出せない。
- 実装の誤りではない（SAT の式どおり、30個の ReLU をすべて置き換え、切り替えは学習の逆伝播と学習中の攻撃だけ）。
- 選択肢 C（β=50）は、このモデルでは本当の勾配とほぼ同じになるので、基準を再現するだけと見込まれ、回さない。
- 解けていない点：SAT の ResNet-50 で「更新だけ」が +2.8 上がった理由（ResNet-18 ではずれがさらに小さく、ずれの大きさだけでは説明できない）。seed 1本、ホストと決定的モードの違いあり。
