## 選択肢

### A: MobileNetV4-M には足さず、3点グリッドの判定を待つ（推奨）

- **内容**: 新しい GPU の run は入れない。Ferret の lr 0.025 の bundle を読んで記録し（GPU 不要。Ferret のファイルを読む許可が要ります）、
  lr 0.05 の完走後にその postrun を行い、3点で判定する。空いた Hamster GPU0 は、保留中の 0026（stage 2）などに回す
  （たとえば 0026 の A を選ぶなら、2本の stage 2 を相乗りではなく GPU0 と GPU1 に1本ずつ流せます）。
- **GPU時間**: 0（MobileNetV4-M について）。
- **分かること**: 承認済みの範囲での MobileNetV4-M の最良の lr と、その best の値。これで MobileNetV4-S・EfficientNet-B0 などと best 同士で並べられます。
- **事前登録ルール**: 3点のうち、best の内部検証 PGD-10 が最も高い lr を MobileNetV4-M の lr とする（A2 の「調整の予算をそろえ、best 同士で比べる」）。
  1位と2位の差が 1pt 未満なら「この2点は見分けられない」と書き、両方を並べて報告する（どちらを採るかは人間が決める）。
  最良が端（0.0125 か 0.05）にあり、隣との差が 1pt 以上なら、「本当の最良は範囲の外にあるかもしれない」と注記する。
- **リスク**: 最良が下端の 0.0125 になった場合、範囲を広げるかどうかをその時点で決めることになり、そこから約35時間かかります。

### B: 下端に 0.00625 を今から足す

- **内容**: `..._phase1_random_lr000625.yaml`（lr 以外は今回と同じ）を作り、pinned worktree から Hamster GPU0 で始める。
- **GPU時間**: 約33〜37 GPU時間（実時間も同じ）。config の追加とテストに少し。
- **分かること**: lr 0.0125 が最良だった場合に、さらに下で伸びるかどうか。
- **事前登録ルール**: 3点の判定（A と同じ）で 0.0125 が最良のときだけ、この結果を使う。
  0.00625 の best PGD-10 が 0.0125 より 1pt 以上高ければ「最良はさらに下」とし、範囲の外の可能性を注記する。
  差が ±1pt 以内なら 0.0125 を採る（予算の少ない方を採るのではなく、承認済みの点を優先）。1pt 以上低ければ 0.0125 が最良で確定。
  3点の判定で 0.0125 が最良でなければ、この run は記録だけして判定に使わない。
- **A2 との関係**: A2 は「モデルごとに調整の予算をそろえる」です。MobileNetV4-M だけ4点にすると予算がそろわなくなります。
  他のモデルも下端で最良になったときに同じように1点足す、という決まりを先に決めない限り、この選択肢は A2 に反します。
- **リスク**: lr 0.025 か 0.05 が最良なら、35 GPU時間が判定に使われません。
  今回のピークの段階がまだ伸びていたことは、lr が低すぎる兆しとも読めるので、0.00625 で良くなる見込みは高くないと考えます。

## 推奨

A を勧めます。lr 0.0125 の結果だけでは、最良の lr が下端にあるかどうかは分かりません。
ピークの lr の段階が終わる時点でまだ伸びていたことは、むしろ lr を上げた方が良い可能性を示しています。
lr 0.025 はすでに完走していて、記録するだけで判定の大半が見えます。lr 0.05 も今日〜明日に終わる見込みです。
B は、当たる見込みの低い賭けに約35 GPU時間を使い、さらに A2 の予算をそろえる原則を崩します。
空いた Hamster GPU0 は、判定待ちの 0026（stage 2）に回す方が、プロジェクト全体の判定を早めます。
推奨が変わるのは、Ferret の lr 0.025 を読んだ結果、0.0125 が 0.025 より 1pt 以上高かった場合です。
そのときは下端を広げる意味が出てくるので、A2 の扱い（全モデルに同じ決まりを当てるか）と合わせて B を考える価値があります。
