# 0036 — ERT online routing proxy and attack-objective diagnostics

Status: `planned / CPU diagnostics first`
Date: 2026-08-11

## Objective

Before introducing dynamic hard routing, determine whether the existing
training-time KL-PGD10 state is a usable proxy for the stronger CE-PGD20
oracle, whether S1 transitions require a special route, and whether the
already-collected CE/KL attack factorial changes the interpretation of the
state signal. This plan is diagnostic only; it does not select a threshold,
route, coefficient, or intervention.

## Frozen contract

- Primary teacher: Chen ERT, L2/seed 1 and L4/seed 2.
- Feature anchors: 39, 59, 79. Future-failure endpoint: terminal epochs
  189/194/199, majority means wrong on at least two of the three.
- Oracle state uses the existing CE-PGD20 strong replay. Online state uses the
  existing inclusive KL-PGD10 `SampleStateStore` anchor rows. No attack is
  regenerated by this diagnostic.
- Top-K is analysis-only: K equals the observed FF count within the eligible
  current-correct cohort. It cannot calibrate a production threshold.
- Oracle and online fragile-correct state use a fixed lower 10% of the current
  robust-correct cohort, with `(risk, stable_id)` deterministic ties. The 20%
  overlay is not used for selection.
- Existing CE/KL×PGD10/20 factorial artifacts are read-only. No official test,
  AutoAttack, training, or unused confirmation seed is used.
- Per-epoch online state is absent. Only 39→59→79 snapshot transitions are
  reported; one-epoch delayed routing is blocked rather than interpolated.

## Diagnostics

1. FF-count Top-K precision/recall/Jaccard/lift for teacher signed dominance,
   strong student margin risk, online margin-EMA risk, online frequency risk,
   teacher clean-margin risk, and a fixed `mT_clean + DeltaT` rank score.
2. CE-PGD20 oracle versus KL-PGD10 online margin correlations, correctness
   agreement, wrong precision/recall, and S1/S2/S3 confusion.
3. S1/S2/S3 snapshot transitions, flapping counts for available 20-epoch
   intervals, and endpoint FF/recovery rates.
4. S1×T3 counts, teacher clean-correct/wrong split, and future degradation
   versus S1×T1/T2.
5. Existing CE/KL×PGD10/20 factorial validation/feature summaries, explicitly
   separated from new training claims.

## Acceptance and outputs

- Public CPU CLI, fail-closed stable-ID/class/lineage joins, deterministic
  metrics, and no overwrite.
- Machine report: `docs/experiments/ert_online_routing_proxy_v1.json`.
- Human report: `docs/ERT_ONLINE_ROUTING_PROXY_RESULTS.md`.
- Focused unit tests and `scripts/verify.py --changed` once after the delta.
- Any missing online teacher-forward or one-epoch data is reported as
  unavailable, never reconstructed from a different attack or snapshot.
