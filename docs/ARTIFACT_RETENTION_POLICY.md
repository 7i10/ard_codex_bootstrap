# 成果物の保存方針

- 状態: 発効（2026-09-06）
- 適用: Hamster / Ferret 上の全成果物

## 分類の軸は「再生成コスト」

以前は「再生成可能／不可能」と呼んでいたが、これは誤りだった。
訓練は決定論的であることが確認されており（同一 seed・同一環境で
model `state_dict` のバイト列が一致）、環境は `requirements/environment.lock` で
固定されている。**手順と環境が揃っている限り、checkpoint はすべて再生成できる。**

したがって軸は可否ではなく**コスト**であり、判断は**保存対象か否か**である。

| 階級 | 定義 | 例 |
|---|---|---|
| **再生成不能** | 生成手順そのものが存在しない、または失われている | git 未 push のコミット、ソース SHA や環境世代が特定できない旧成果物、人が書いた記録 |
| **再生成高コスト** | 手順はあるが再取得が高い | （現時点で該当なし。下記参照） |
| **再生成低コスト** | 手順があり、数 GPU 時間で戻せる | I100 親 checkpoint（3.5 GPU 時間）、e99→e199 の確定ラン（3.5 GPU 時間）、評価出力 |

## 現時点の実態

I100 系の実測は **2.08 分/エポック**である。したがって

- 親 1 本（100 エポック）= **3.5 GPU 時間**
- 確定ラン 1 本（e99→e199）= **3.5 GPU 時間**
- 親 6 本一式 = **21 GPU 時間**（3 ヶ月の利用可能量の約 0.2%）

**「高コスト」に該当する成果物は今のところ存在しない。**

## 保存方針

1. **git に入るものはすべて保存対象。** コード、設定、プラン、結果記録（JSON / Markdown）、
   sha256 サイドカー、`external.lock.yaml`、`environment.lock`。
   これらは再生成不能であり、唯一の本質的な保存対象である。
2. **再生成不能な旧成果物のみ、W&B へ退避する。**
   具体的には、ソース SHA・環境世代・親系譜のいずれかを特定できない過去の checkpoint。
   復旧後の棚卸しで特定する。
3. **再生成低コストの checkpoint は保存対象としない。**
   バックアップ基盤を作らない。必要になったら作り直す。
   `docs/ARTIFACT_LOCATION_MAP.md` に所在だけ記録する。
4. **NFS への複製は行わない。** 速度の代償に見合わない（決定済み）。

## この方針が成立する前提

次のいずれかが崩れたら、方針を見直す。

- 訓練の決定論性（実データ長期ランでは未検証。検証項目として残っている）
- 環境の固定（`environment.lock` からの逸脱がないこと）
- 生成手順の記録（プランと結果記録にソース SHA・親・seed が残っていること）

**3 番目が最も脆い。** 記録が欠ければ「再生成低コスト」は即座に「再生成不能」に落ちる。
記録を git に置くことが、バックアップ戦略そのものである。
