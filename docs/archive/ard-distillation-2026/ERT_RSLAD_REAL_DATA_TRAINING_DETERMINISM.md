# 実データ長期ラン決定論性の検証

- 状態: 完了（2026-09-06）
- ホスト: Ferret、GPU 0（RTX 4090）
- 環境: `adv`（Python 3.12.13）。`ard-v2` は当時 timm 欠落のため起動不能だった
- 目的: `docs/ARTIFACT_RETENTION_POLICY.md` と最終再現計画が依拠する「訓練は決定論的」という前提を、
  合成データ 3 エポックではなく**実データ・本番設定・15 エポック**で確かめる

## 設計

`I100_CONTROL` を dev-1 親から e100→e114 まで、**同一 GPU・同一設定で 2 回**走らせた。

| 項目 | 値 |
|---|---|
| 親 | `parent-dev1.pt`、`sha256 = 360910a8…7630835`（plan 0087 の正典 dev-1 親と一致） |
| 設定 | `protocol: controlled_cifar10_r18_stagewise_augmentation_v1`、`deterministic: true` |
| 教師 | `Chen2021LTD_WRN34_10`、`sha256 = fc398a48…c383983` |
| 区間 | e100–e114（15 エポック）、endpoint checkpoint は e104 / e109 / e114 |
| 実時間 | run A 35 分、run B 36 分 |

判定は **model `state_dict` のバイト列**で行った。checkpoint のファイルハッシュは判定に使わない。

## 結論

**実データ・本番設定・15 エポックの連続訓練は決定論的である。**

したがって次が成立する。

- 最終段階で提案手法をエポック 0 から再実行し再現を確認する計画は、実行可能である
- checkpoint は「再生成低コスト」であり、保存基盤を作る必要はない
  （`docs/ARTIFACT_RETENTION_POLICY.md`）
- **checkpoint のファイルハッシュを再現性の判定に使ってはならない。** 下記のとおり
  重みが完全一致していてもファイルは異なる

## 副次的な発見：実験実行中のコミットは run 識別子を変える

2 回のランで checkpoint ファイルのハッシュは異なった。中身を比較すると、
重み・optimizer・scheduler・RNG・sampler 状態はすべて一致しており、
異なるのは次の 3 つだけだった。

- `config_hash`
- `tracker_run_id`
- `fork_lineage`

原因は**私が run A の実行中にリポジトリへコミットしたこと**である。run A は
`b928dc7`、run B は `ee6364f` を HEAD として記録した。両者の差分は
`requirements/environment.lock` の 25 行のみで、`src/` `scripts/` `configs/` の
変更は 0 だったため、重みは一致した。

2 つのことが言える。

1. **来歴機構は正しく働いた。** コードが同一でも、ソース SHA が違えば
   2 つのランは形式的に別設定として記録される。実際の比較であれば
   aggregator の照合で弾かれる。
2. **手続き上の誤りである。** 走っているランのソースツリーにコミットしてはならない。

したがって規則を 1 つ追加する。

> **キャンペーンの実行中は、そのソースツリーにコミットしない。**
> 実行前にソース SHA を固定し、全アームが同じ SHA を記録することを完了時に確認する。
